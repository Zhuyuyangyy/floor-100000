## 1. 口径与方法（可复算）

蒙特卡洛**不重写引擎**：每个 runSeed 直接 `createNewGame(seed)` → `invest()` →
循环 `state.day = 2..30` 调真实 `settleInvestments()`（内部
`makeRng(deriveSeed(runSeed, 当日, 'venture', 产业id))`）。因此模拟与线上玩法
逐字节同一条代码路径，不存在"测试里的模型和游戏里的规则两套"的风险。

- **样本**：runSeed = 1..2000，每 seed 一局。
- **窗口**：第 1 天入股；第 2..30 天依次结算"刚结束的第 1..29 天"，共 29 个
  结算日（与 economyLoop.test.ts 的 venture 扫程同口径，两处数字对得上）。
- **随机源**：全部 seeded RNG。`econBalance.test.ts` 有抛错探针——扫程期间任何
  一次 `Math.random` 调用直接抛错；同 seed 两次扫程逐字段相等（测试钉住）。
- **百分位**：最近秩（无插值），n=2000 时 P10/P50/P90 = 第 200/1000/1800 个。

## 2. 蒙特卡洛结果（2000 seed，30 游戏日窗口）

| 指标 | 宿舍水站 40 金 | 废铁商路 80 金 | 口粮暗线 120 金 |
|---|---|---|---|
| 期望日收益（金） | 1.28 | 4.92 | 10.97 |
| 日收益 P10 / P50 / P90 | 1 / 1 / 2 | 0 / 5 / 8 | 0 / 13 / 19 |
| 30 日期望总收入（金） | 32.45 | 96.42 | 155.88 |
| 总收入 P10 / P50 / P90 | 18 / 36 / 39 | 23 / 115 / 146 | 19 / 148 / 302 |
| **爆仓概率（30 日内本金全损）** | **24.7%**（494/2000） | **57.9%**（1158/2000） | **83.8%**（1676/2000） |
| 平均爆仓日 | 第 14.0 天 | 第 12.7 天 | 第 11.3 天 |
| **本金期望留存** | **75.3%**（30.12/40） | **42.1%**（33.68/80） | **16.2%**（19.44/120） |
| 30 日期望净盈亏（金） | +22.57 | +50.10 | +55.32 |
| 净盈亏 P10 / P50 / P90 | −22 / +36 / +39 | −57 / +36 / +145 | −101 / +28 / +295 |

读法：

- 日收益的 P10=0 是亏损日（没收入、本金还在）；P50/P90 随 `productionDecay`
  逐日枯竭，所以日收益分布整体左偏且越来越低——"早入场"本身就是收益。
- 本金期望留存恒等于 (1 − 爆仓概率) × 成本（爆仓全损、未爆分文不缺），
  测试里按恒等式钉死。
- 口粮暗线的中位结局（+28）低于它的两个下游：83.8% 的局在赚到约 148 金后
  被查扣、只落回 +28，16.2% 的局活满窗口拿到 +295。它是彩票，不是套利——
  与它的风味文本"利润最厚；被查扣一次，整条线全没"精确同构。

## 3. 无支配与参数结论：不动，用数据证明

**支配的判定**：A 支配 B = A 的 30 日净盈亏分布一阶随机优于 B
（对所有 x，F_A(x) ≤ F_B(x)，且至少一处严格）。测试对三个有序对、56 个网格点
（−140..+420 步长 10）双向扫描 empirical CDF，两个方向全部不成立。

三个定性事实（测试逐条钉死）：

1. **收益梯子单调向上**：期望净盈亏 22.57 < 50.10 < 55.32，右尾
   P90 +39 < +145 < +295。
2. **风险梯子同步单调向上**：爆仓率 24.7% < 57.9% < 83.8%，左尾
   P10 −22 > −57 > −101。
3. **没有一门全面更优**：任何"更高期望"的门同时"更高爆仓、更厚左尾"，
   反之亦然。水站中位 +36 ≥ 暗线中位 +28，但期望与右尾全面低于暗线——
   典型的风险取舍形状，不是设计失败。

**因此参数一行未改。** AG-14 拍的三个数（5%/6%/1%、10%/12%/3%、16%/20%/6%）
落在了一个自洽的带里：每上一档，期望收益与爆仓概率同向放大，风险调整后
（期望净盈亏 ÷ 爆仓概率）三档分别约 0.91 / 0.87 / 0.66 金，量级一致；
三档风味（本小利薄 / 吃差价 / 查扣全没）与实测画像逐条对得上。改动它们
是在没有证据的情况下重拍一遍。

**组合侧面**（同一扫程里同时持有三门，240 金）：

- 期望净盈亏 +127.98 = 三门之和（期望线性叠加；三门 RNG 流按
  (seed, day, id) 独立，测试按"全灭概率 ≈ 爆仓率之积"验证独立性：
  实测 12.3% vs 乘积 11.98%）。
- 中位净盈亏 +111，高于任何单门的中位（+36/+36/+28）——分散化把中位数
  抬起来了；全灭 12.3% 远低于最高单门的 83.8%。组合是合法的稳健打法。

## 4. divest：流动出口的设计（AG-14 §10.2）

```ts
divest(state, ventureId): DivestResult
// { ok: true; gold; refund } | { ok: false; reason }
```

**回收价 = 入股成本 × 70%**（`DIVEST_REFUND_RATE`，40/80/120 → 28/56/84，
IEEE754 下精确整数，无舍入争议）。不全价退的四条理由：

1. **全价撤资 = 零成本期权**：任何一天的倒塌/亏损都能用"进—撤—进"绕开
   （倒塌前一刻撤出即无损），AG-14 的全部风险参数在数学上作废。折扣必须 > 0。
2. **30% 同时是防刷成本**：invest→divest→invest 每圈固定烧 30% 本金
   （12/24/36 金）。想靠循环刷财富经验（每圈 +50 XP）必须真金白银地烧，
   ~90 圈才能喂满一条线——测试钉住"每圈 +50 ×2、烧 12"。
3. **折价幅度有语义锚**：商品 round-trip 损耗 50%（买 12 卖 6）。撤资取 30%
   ——撤资是主动管理，不是走投无路的半价甩卖；倒塌的 100% 全损仍在更下面，
   三档损失（30% 撤资 / 100% 倒塌 / 0 持有）界限分明。
4. **不是占优策略**：立即撤资（0.7×成本）在任何一门都被"持有 30 日"的期望
   总值严格优于（测试与蒙特卡洛对联钉死）。撤资因此是应急出口——终局前把
   沉没资本盘活、被冒险决策救急——而不是每局开局的标准动作。

**幂等与原子**：不在册（从未入股 / 已撤 / 已倒塌出局）一律拒绝且分文不动；
未知 id 与 invest 同口径拒绝（存档里的幽灵 id 不清账，settleInvestments 同一
宽容度）。重复调用不会重复退款（测试钉住第二次调用的逐字段不变）。

**不给经验**：契约 §5 只登记"完成一笔产业投资 +50"；撤资是流动性操作，与
"亏损/倒塌不喂经验"同一哲学——经验只奖励正向完成。

**存档**：divest 只改 `growth.ventures` / `growth.investedGold` / `player.gold`，
三者都在 growth profile 里随 `serialize` 天然往返，SaveSystem 零特殊处理。
测试钉住 round-trip 后：账本正确、`validateGameState` 无异议、读回来的档
继续按日结算且只付在册的那一门（撤走的商路分文不再进账）。

**可再入股**：撤过的门可以重新进（一种一门的限制只在册时生效）——卖出水摊
再盘一间是合理动作，30% 折价就是这个选项的价格。

## 5. canCraft 语义统一：已建造即不可建（AG-42 §5.2）

**选择"拒"而不是"文档辩解"**：`canCraft(state, id)` 对已建造的配方现在返回
`{ ok: false, missing: [], reason: '<名称> 已建造' }`，与 `craft()` 共用同一道
第一闸门（先已建造，再前置，再材料——craft() 本来就是这个顺序）。

理由：材料再齐，已建成的设施也没法再建一次。"这条配方现在能建吗"的诚实
答案是不能；让谓词与执行分叉，只会逼每一个调用方各自补一遍 hasUpgrade
（GameScene 现在就补了，`built ? '已建'` 掩盖了分歧）。

**形状 additive**：拒绝走既有的可选 `reason` 字段（AG-42 加 hints 时就是
additive 路线），`CanCraftResult` 与 `missing` 数组形状一个字未动。
`craftingSystem.test.ts` 的 `toContainEqual` 钉死不受影响。

**既有断言零修改**：craftingSystem / passChain / economyLoop / craftLoop 四个
文件的 canCraft 断言全部落在"未建造"状态上（逐条核对过），新语义下原样
成立——没有需要"修"的既有断言，也没有删过或放宽任何一条。新语义由
econBalance.test.ts 钉住（已建造+材料齐 → 拒；craft() 同样拒且不扣料；
built 检查优先于 gate 与材料；缺料/缺前置的旧语义逐条复钉；recipePreview
对已建造配方保持 coherent：built=true / canCraft=false / missing=[]）。

**UI 零影响**：GameScene.refreshCraft 的 `built ? '已建' : ...` 三元里 built
优先，状态文字与颜色一个像素没变（没有场景测试钉这段文字，也已核对）。

## 8. 未处理干净的地方（留给属主/后续）

1. **invest→divest→invest 的 XP 兑换率**高于买面包（12 金/50 XP vs
   12 金/10 XP）。这是 30% 折价换来的显式定价，~90 圈（≈90 游戏日 + 约 1080
   金）才能喂满 wealth 一条线，我认为是可接受的"昂贵的成长路径"而非漏洞；
   若属主认为财富经验只该来自交易达成，收口点是给 invest 也加"同门重新
   入股不重复给 XP"或按净投入给经验——那是 growth 契约的变更，不在本工单。
2. **手改档的幽灵 venture id**（ventures 里有未知 id）divest 会拒绝、账本上
   的 investedGold 也不会为它减记——与 settleInvestments 的既有宽容度一致，
   但没有自愈路径。要自愈需要在 core/growth.ts 的 normalize 里加白名单过滤，
   那是 core，不属本工单。
3. **VC 组合的联合分布只验到独立性近似**（全灭/全存 vs 边际积，tol 0.05），
   没有做完整的 copula 检验；RNG 流按 (seed, day, id) 派生，结构性独立，
   深度检验收益递减。
