# 模块所有权与文件修改边界（Wave 0 草案）

> **状态：提案，待项目负责人确认。** 本文件位于仓库外的 Wave 0 草案目录，不是已提交或已生效的仓库政策。职责基于项目总指令和 2026-11-13 审计摘要；没有在本次写作时重新拉取仓库或逐一核验文件。所有权表示模块负责人和审查责任，不代表自动获得跨模块修改、合并或发布权限。

## 协作原则

1. 一个 Task ID、一位负责人、一组明确的文件范围；同一时段一个文件只允许一个 Agent 写入。
2. 模块 Agent 仅修改本表中明确归属自己的文件。未列明的文件默认**未分配**，不得据此推定为可改。
3. 跨模块接口或共享文件需要先提交接口变更说明，相关所有者确认后，由 Lead 统一接线和集成。
4. 每个 Agent 同一时间只承接一个 Task ID；所有开发须使用独立 worktree 或等效隔离环境，并从重新确认的集成 SHA 起步。
5. 本轮为 Wave 0：只允许状态审计、任务登记、所有权和接口规划，不启动大规模功能开发。

## 角色与拥有范围

|---|---|---|

| **Agent A — NAVIGATION** | `src/systems/FloorSystem.ts`、`src/systems/TowerNav.ts`、`src/systems/shortcut.ts`、明确指定的楼梯/相机/导航专属测试 | 可以负责导航规则和模块内测试；不得重写 `GameScene.ts`、改变生存数值或直接增加楼层内容。与场景切换、共享存档或 UI 的改动须先取得 Lead 及相关所有者同意。 |

## 共享与受限表面

- **共享核心：** `GameScene.ts`、`gameState.ts`、`gameTypes.ts`、`main.ts` 由 Lead 负责修改和集成。模块 Agent 如需要改动，先提交接口提案和最小文件清单。
- **视觉共享风险：** `uiKit.ts` 的准确路径、当前基线内容及最终所有者尚待确认。审计摘要指出它与 `GameScene.ts` 存在 PR/工作区重叠风险；在明确裁决前按受限共享文件处理，不允许并行编辑。
- **系统间目录交界：** 各 Agent 只拥有上表明确列出的文件。`src/systems/` 中未列名文件、配置、脚本、依赖清单、构建配置和 CI 文件均未自动分配，须由 Lead 按任务指定所有者。
- **测试归属：** QA 对测试基础设施和跨模块回归负责；模块 Agent 可在自己的独立测试范围内补测试。任何测试移动、删除、断言降级及 CI 阻断策略变化都需 Lead 审查。
- **资源归属：** VIS 可在获批任务内添加视觉资产；不得覆盖或清理既有未跟踪素材。素材来源、许可、尺寸和加载路径应随交付记录。

## 交接与冲突处理

跨界任务开始前，任务记录至少要写明：Task ID、负责人、基线 SHA、精确文件白名单、接口变化、依赖、验收方法和冲突处理人。发现另一 Agent 正在修改同一文件时立即停止写入并报告 Lead；不得自行重置、清理、覆盖或挑拣另一工作树的改动。Lead 负责指定唯一写入者或拆分任务，完成后记录集成 SHA 和验证结果。
