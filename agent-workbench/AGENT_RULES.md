# 十 Agent 并行开发硬规则

## 1. 分支与隔离

- 每个 Agent 使用自己的分支和独立 Git worktree。
- 本轮基线 SHA：`adaec3b27cb16eebd5106d0971a54c79c0af0b1e`。
- 每个 Agent 只改任务书中列出的文件白名单。
- 不得在同一 worktree 里启动两个 Agent。
- 不得直接修改 `main` 或 `feat/tower-zoom-b2`。
- 所有 PR 目标分支统一为 `feat/tower-zoom-b2`。
- PR 默认 Draft；未经项目负责人批准不合并。

## 2. 禁止操作

- 禁止 `git reset --hard`、`git clean -fd`、强制覆盖、删除他人未跟踪文件。
- 禁止批量格式化整个仓库、全局重命名、无关依赖升级。
- 禁止删除/skip 测试、弱化断言、伪造状态或把失败测试写成通过。
- 禁止把密钥、模型权重、推理缓存、个人日志或本地 .env 提交 Git。
- 禁止改动冻结设计、基础经济数值、胜利条件和剧情 canon，除非项目负责人明确批准。
- 禁止多个 Agent 同时写同一个文件；发现冲突立即停止写入并报告 AG-01。

## 3. 接口规则

- 核心状态、存档 schema、`GameScene.ts` 属于共享高风险表面。
- `GameScene.ts` 本轮仅 AG-02 有权修改。
- `src/core/gameState.ts`、`src/core/gameTypes.ts`、`src/main.ts` 由 AG-01 统一审查；任何 Agent 需要字段变更，先提交接口提案。
- AI 只提议、规则只裁决、游戏才执行；NPC AI 不得直接修改 GameState。
- UI 只发出意图，不得自己结算交易、物品或战斗规则。
- 新世界生成、经济模拟、NPC 库存模块先独立实现；没有接口批准前不得强行接入 GameScene 或存档。

## 4. 提交规则

- 一个 Issue 对应一个 Task ID。
- 一个 PR 尽量只包含一个 Task ID。
- 提交前运行任务要求的检查，记录真实命令和结果。
- PR 描述必须包含：Task ID、基线 SHA、文件范围、改动摘要、测试证据、截图/trace、已知问题。
- 不得把别的 Agent 的提交 cherry-pick 到自己的分支，除非 AG-01 明确安排。

## 5. 停止条件

遇到以下情况必须停工并报告：
- 基线 SHA 变化或分支不是指定起点。
- 需要修改白名单外文件。
- 发现已有 PR 与本任务存在同文件改动。
- 发现设计冲突、存档兼容风险、交易守恒或生存规则变化。
- 两次尝试仍无法复现/修复同一问题。
- 测试环境无法启动或证据不完整。

## 6. 交付要求

每个 Agent 最终必须交：
1. PR 链接和分支名。
2. 文件改动清单。
3. 功能/设计决策。
4. typecheck、unit、build、相关 E2E 的实际结果。
5. 关键截图、trace 或生成报告路径。
6. 未解决问题和建议的下一步。
