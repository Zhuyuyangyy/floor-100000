# B2 可缩放塔楼架构方案（修订版）

- 状态：**待批准**（2026-10-26 修订，取代上一轮对话中的原方案）
- 上游依据：`docs/GAME_DESIGN_LOCK.md`（核心设计已冻结）
- 本轮范围：**只出方案与差距清单，不实现 B2 代码**

---

## 1. 相对原方案改了什么

原方案的技术选择（总览 + 楼层群共用 `TowerOverviewScene`，具体楼层继续用 `GameScene`）**经复核仍然成立**，保留。

被推翻的是原方案把塔楼当成**静态地图**的设计假设。原 `TowerModel` 只有「供电/断电/危险/资源」四种标记，无法承载阶级社会。修订后 `TowerModel` 升级为**社会空间数据模型**（见 §3），并加入两条硬规则：

- **玩家从第 1 层开始**，不是第 100000 层。
- **总览不可传送**。点击楼层只做「选择/查看」，实际移动必须走已解锁的通行路径。

### 1.1 实施顺序修订（2026-10-26 项目负责人审定）

**「起始层重映射」从 B3 提前到 B2 必做范围。** 原路线图让 B2 原型继续用第 100000 层开局、B3 再改回第 1 层，这被明确否决——核心设计已冻结，不能为开发方便沿用与设计冲突的假设，否则必然返工。

因此 B2 的完整范围是：

1. 新游戏从第 1 层底层贫民区开始。
2. `TowerModel` 支持 100 个区段与完整 1–100000 楼层编号。
3. 塔楼总览 / 楼层群 / 楼层细节三层视图导航。
4. 当前楼层持续高亮；远端楼层只可查看与规划，不可无条件传送。
5. 保留 `GameScene`、生存状态、背包、制作、家具交互与存档逻辑。

**第 100000 层的处置**：原 v0.1 宿舍模板**保留为开发测试场景**，只能通过独立的测试配置（`?devfloor=` 查询参数）进入，**不再是正式新游戏的默认出生点**。正式路径下第 100000 层属于统治核心，首版不提供进入。

**胜利条件**：v0.1 的「活到第 8 天」按设计冻结文档 §7 降级为**阶段性生存目标**，不再作为终局。B2 不改生存数值与死亡判定，只把 HUD/帮助文本中的目标描述从「熬过 7 天」改为「向上攀升」。

## 2. 三层视图与导航

| 视图 | 职责 | 数据精度 |
|---|---|---|
| **塔楼总览** | 观察整栋楼的状态分布、定位自己、规划路线 | 100 个区段 × 1000 层的聚合状态 |
| **楼层群** | 展开单个区段，看十几到几十层的结构与危险标记 | 区段内楼层的紧凑行数据 |
| **楼层细节** | 现有 `GameScene`：移动、交互、搜集、制作、生存 | 完整楼层场景 |

**导航规则**：
- 滚轮 = 以鼠标位置为中心缩放（总览 ↔ 楼层群）
- 拖动 = 平移塔楼
- 点击楼层 = **选中并查看**，非传送
- 返回按钮 = 回上一级视图
- **当前所在楼层始终高亮**，缩放多次后仍能定位自己
- HUD 不随世界缩放变形（`setScrollFactor(0)` + 独立 depth）

## 3. TowerModel 数据模型

按设计冻结文档 §3/§4 的要求，每个楼层记录至少包含：

| 字段 | 用途 |
|---|---|
| `floorNumber` | 楼层身份 |
| `sectorId` | 所属区段（100 层一段中的哪段） |
| `tier` | 阶层（1–6，对应六个社会区域） |
| `zoneType` | 区域类型（贫民/工人/工业/商业/特权/统治） |
| `resourceLevel` | 资源等级（驱动底层匮乏、高层富饶的梯度） |
| `dangerLevel` | 危险等级（探索风险） |
| `security` | 安保状态（通行限制） |
| `faction` | 所属势力/控制者（派系、委托、起义的基础） |
| `accessLevel` | 玩家通行资格 |
| `explored` | 已探索状态（持久化） |
| `worldFlags` | 重要世界变化（持久化） |

**规模约束**：十万层**不创建十万个完整对象**。未探索区域只存聚合状态；进入楼层后才生成详细内容；楼层明细由 `floorTemplates` 的可复现程序化生成推导。

**扩展接口**：`faction` / `accessLevel` / `worldFlags` 三个字段首版可以恒为初值，但**字段必须存在**，否则后续社会系统无处落地。

## 4. 架构约束与模块划分

| 模块 | 形式 | 职责 |
|---|---|---|
| `TowerModel` | 纯 TS，可单测 | 区段聚合、阶层梯度、通行资格判定 |
| `TowerOverviewScene` | 新 Phaser Scene | 总览 + 楼层群（摄影机缩放分级） |
| `GameScene` | **不改动** | 楼层细节生存玩法 |
| `session` / `SaveSystem` | **不改动** | 状态跨视图保持（GameState 本就是模块级单例） |

**不引入大型依赖**，不改物品 ID、制作配方、交易规则、生存数值。

**像素清晰**：摄影机 zoom 取整数值；禁止亚像素抖动与非预期模糊。

## 5. 风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| 楼层群渲染上千行对象拖垮帧率 | 高 | 只渲染视口内约 20 行，滚动时回收 |
| 缩放导致像素模糊/抖动 | 高 | zoom 取整；HUD 独立于世界缩放 |
| 视图切换丢失玩家状态 | 中 | GameState 为单例；补 e2e 断言「总览→细节→返回后 currentFloor/HP/物品不变」 |
| `Scale.FIT` 与塔楼逻辑高度的坐标转换 | 中 | 鼠标坐标统一走 `camera.getWorldPoint` |
| 总览被误用为传送器 | 中 | 点击只选中；进入楼层前必须过通行资格判定 |
| 与现有 35 条 e2e 冲突 | 低 | 不改 GameScene 入口逻辑，仅在 MenuScene 加入口 |

## 7. 差距清单（现状 vs 新设计）

| 能力 | 现状 | 目标 | 差距 |
|---|---|---|---|
| 起始楼层 | 100000 | 1 | **大**：配置、模板、常量、HUD 文本、场景门禁 |
| 楼层数量 | 5 层固定模板 | 100000 层按需生成 | **大**：需 TowerModel + 程序化模板 |
| 塔楼总览 | 无 | 三层视图 | **大**：全新 Scene |
| 通行资格 | 无（相邻即可走） | 门禁/安保/资格判定 | **大**：新系统 |
| 阶层梯度 | 无 | 6 阶层资源/危险梯度 | **中**：数据模型 + 模板参数化 |
| 社会关系 | 2 名 NPC 简易交易 | 人脉/声望/派系 | **大**：新系统 |
| 成长路线 | 无 | 四条互相影响 | **大**：新系统 |
| 终局 | 活到第 8 天 | 四条路线自然形成 | **大**：新系统 |
| 生存/搜集/制作/建设 | **已完成且经过测试** | 保留 | **无** |
| 物品/配方/交易规则 | **已完成** | 保留 | **无** |
| 像素美术资产 | **已完成（35 张）** | 保留为细节素材 | **无** |

## 8. 分阶段路线图
