## 最终愿景

> **从底层求生，向顶层夺权。**

一款拥有**十万层世界、真实生存循环、资源经济、人物关系与阶级斗争**的 2D 像素生存沙盒。

玩家从第 1 层的贫民宿舍开始，最初为了食物、饮水和安全发愁。随着探索深入，逐渐拥有自己的住所、制作能力、财富、人脉和影响力，最终可以成为权贵代理人、商业巨头、起义领袖，甚至改变整座塔楼的统治秩序。

**以后所有开发决策都要服务这个目标。** 我们追求的不是每天增加多少行代码，而是每个阶段都让游戏离这个愿景更近一步。先让一个底层居民真实地活下来，再让他逐渐获得财富、人脉与权力，最后让整座十万层塔楼成为一个有生命、有矛盾、能够被玩家改变的世界。

## 六条原则（锁死，不再反复改方向）

| # | 原则 | 含义 |
|---|---|---|
| 01 | **十万层塔楼是整个世界** | 第 1 层至第 100000 层属于同一个逻辑世界。总览、楼层群、房间细节必须连贯，不是三款游戏。 |
| 02 | **玩家从底层开始向上攀升** | 第 1 层是正式出生点，第 100000 层是最高权力核心。旧的高层开局只保留开发测试用途。 |
| 03 | **越往上，资源与风险都升级** | 上层有更先进的技术、更丰富的物资和更高的财富，但门禁、安保、派系斗争和政治风险也更复杂。 |
| 04 | **生存循环必须真实成立** | 探索、搜集、消耗、制作、交易、返回基地和继续探索形成闭环，不能只有界面和按钮。 |
| 05 | **人物关系与权力是长期动力** | 资源不仅用于活下去，还能交换人情、获得资格、影响势力，最终改变塔楼秩序。 |
| 06 | **不因局部实现困难而推翻整体架构** | 保留 Phaser + TypeScript + Electron 和现有成果。优先修复与增量扩展，重大设计变更必须经项目负责人批准。 |

数值、配方、家具、灯光和任务可以不断调整；**以上六条不能因为想走捷径就被改变。**

## 产品里程碑

不应该等到十万层、所有 NPC、所有结局都完成之后，才第一次认真评估游戏好不好玩。

| 里程碑 | 内容 | 达成标准 |
|---|---|---|
| **M1 可玩原型** | **B2 + B3** | 玩家从第 1 层开始，能在五层范围内探索、搜集、管理物资、制作、返回、睡觉和存档。没有关键软锁，没有明显的无限资源漏洞。 |
| **M2 完整的首个章节** | **B4 + B5 + B6 的必要子集** | 更丰富的楼层、资源梯度、基地升级、居民委托，以及一条清晰的向上发展路径。玩家开始理解为什么值得冒险去更高的楼层。 |
| **M3 具备长期游玩价值的正式游戏** | **B7–B10** | 阶级与权力系统、不同发展路线、足够丰富的世界内容、稳定的存档与性能，以及真正经过玩家反馈验证的平衡。 |

> **M1 最重要：它应该先让你自己愿意玩，再去扩大世界规模。**

## 每个任务的固定流程

1. **先确认目标**：这个任务属于哪个里程碑，解决什么玩家问题？
2. **先审计现状**：已有实现是什么，哪些地方确实有缺陷？
3. **明确范围**：这轮只完成一个清晰的任务，不顺手重构整个项目。
4. **先写测试**：关键规则优先用 TDD 验证。
5. **真实验收**：测试、构建、浏览器截图和必要的人工试玩相互配合。
6. **更新文档**：记录实际完成的内容、剩余问题和下一步。
7. **停止等待**：没有授权就不自动进入下一个阶段，不擅自合并 `main`，不发布安装包。

# B2 · 塔楼世界与导航 ✅

**里程碑 M1 · 已实现，待人工验收**

### 目标与玩家价值
把「第 100000 层」从一个静态 Demo 房间变成一座**结构真实**的塔：玩家从第 1 层贫民区醒来，可以查看整座塔、查看任一区段、查看任一楼层详情，并只能通过实际打通的通路进入已解锁的楼层。

### 交付物
- `src/core/tower.ts` — `TowerModel`：100000 层的纯函数聚合视图（不按层存对象）
- `src/systems/TowerNav.ts` — 三层导航的纯状态机（总览 / 区段 / 楼层）
- `src/scenes/TowerOverviewScene.ts` — 渲染与输入，滚轮缩放、拖动平移、点击与键盘均可操作
- `src/core/devMode.ts` — `?devfloor=` / `?devwin=` 开发专用夹具开关
- 起始层重映射：五层模板 100000→1、99999→2、99998→3、99997→4、99996→5
- 第 8 天自动胜利从生产逻辑移除（保留 `?devwin=1` 夹具）
- 总览在默认缩放下完整显示全部 100 个区段（B2 验收修复）
- 塔楼方向修正为「底层在下、顶层在上」，并带 HUD 感知的滚动边界（B2 验收修复）
- 架构与实现记录：[`B2_TOWER_ARCHITECTURE.md`](B2_TOWER_ARCHITECTURE.md)

### 验收标准
- [x] 新游戏从第 1 层开始；第 100000 层仍是合法逻辑楼层与未来终点，但不再是出生点
- [x] 三层导航完整可用：总览 → 区段 → 楼层详情，ESC 逐级返回
- [x] 当前楼层 / 当前区段始终高亮，打开地图即定位到玩家所在区段
- [x] **地图选中不等于传送**：只有 `canEnter()` 通过的楼层才能进入
- [x] 返回地图后玩家位置、生命、物资、时间、探索状态不丢失
- [x] 总览默认缩放可见全部 100 个区段，起点/终点有明确标注
- [x] 塔楼方向与「向上攀升」一致，任意缩放下内容不被 HUD 遮挡

### 不在本阶段实现
程序化楼层生成、社交模拟数据、经济、NPC 关系、终局系统、美术定型。

# B4 · 十万层世界生成

**里程碑 M2**

### 目标与玩家价值
把 B2 的聚合视图变成**可生成、可探索、可复现**的真实世界：100 个区段各自成体系，底层贫困、上层富饶的世界梯度成立。

### 前置依赖
B3 的生存循环（生成的内容必须服务于玩法）。

### 交付物
- 100 个区段的程序化楼层生成器（种子可复现）
- 按需生成 + 探索记录（不为 10 万层预分配对象）
- 六大阶层的资源分布与危险度曲线
- 区段间通行条件（钥匙、权限、体力、通路）

### 验收标准
- 同一世界种子重复生成结果一致；不同种子有差异但难度曲线一致
- 跨区段生成不产生可感知卡顿
- 已探索楼层在返回时内容不变

### 自动化测试
- 生成确定性单测（同种子同结果、跨区段一致性）
- 性能基准测试（生成 N 个楼层的时间 / 内存上限）

### 不在本阶段实现
基地建设、NPC、派系、终局。

# B5 · 资源经济与基地建设

**里程碑 M2**

### 目标与玩家价值
同一件物资既有**生存价值**（喝掉、用掉），也有**经济价值**（卖掉、换通行、换人情），玩家开始在「活下去」和「活得更好」之间做选择。这是冻结设计 §4「同一物品的多重价值」的落地阶段。

### 前置依赖
B4 的世界生成。

### 交付物
- 扩展的物资稀缺度与制作链
- 净水、电力、储存系统
- 宿舍升级（床、工作台、储水、防御）
- 交易与资源价格

### 验收标准
- 资源获取 → 消耗 → 制作 → 升级形成可持续循环，不会无限通胀或彻底枯竭
- 同一物品的多重价值（生存 / 经济 / 政治）在 UI 上可读

### 自动化测试
- 经济平衡模拟（多日资源曲线）
- 制作链完整性单测（每条配方可达）

### 不在本阶段实现
NPC 关系网络、派系、终局。

# B6 · NPC 与社会关系

**里程碑 M2**

### 目标与玩家价值
居民不再是对话树：他们有身份、需求和记忆，玩家的行为会真实改变他们对玩家的态度，从而影响资源、任务和通行机会。

### 前置依赖
B5 的经济系统（NPC 需求需要挂钩到物资）。

### 交付物
- 有身份、需求、关系和记忆的居民模型
- 委托、交易、信任、承诺、背叛和通行资格
- 玩家行为 → NPC 态度的因果链

### 验收标准
- 同一玩家行为在不同关系下产生不同结果
- 关系能实际影响资源获取、任务解锁和通行许可

### 自动化测试
- 关系状态机单测（含背叛与修复路径）
- NPC 记忆持久化（跨存档）测试

### 不在本阶段实现
派系与权力体系、终局。

# B7 · 阶级、势力与权力斗争

**里程碑 M3**

### 目标与玩家价值
向上爬不再只是「打通楼层」：身份门槛、债务、许可证、上层赏识、派系、工人组织、黑市与情报共同决定玩家能走多远。

### 前置依赖
B6 的 NPC 关系网络。

### 交付物
- 身份门槛与许可证系统
- 债务与欠款机制
- 派系（上层 / 工人组织 / 黑市）与情报
- 社会地位的量化与可见反馈

### 验收标准
