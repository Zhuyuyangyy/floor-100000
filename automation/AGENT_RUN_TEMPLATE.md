# 每轮自动化 Runner 的任务模板

将 `{TASK_ID}` 替换为下一条依赖已满足且未完成的任务编号。例如 P0-01。

---

你在开发《第100000层：末日宿舍》。读取仓库根目录的 `CLAUDE.md`、全部游戏设计/技术规范、`docs/03_TASKS.md`，以及当前 Git 历史与任务状态。

本轮仅执行任务 `{TASK_ID}`。先检查其依赖是否满足；如果不满足，停止并报告依赖，不要猜测，也不要跳过。实现前指出最小文件改动集和验收测试。

实现后执行项目现有的 typecheck、unit tests、build 和 Playwright E2E。若 GUI/浏览器不可用则标记“未验证”，不要伪称已通过。涉及画面需至少留一张可检查的截图。若修改当前任务范围之外的文件，说明原因。

使用独立分支提交；如果已获得远端权限，则建立 PR 并提供链接。不要强推或合并 main，也不要自行部署生产环境。绝不提交密钥，不要默认开启无限系统权限。

输出：TASK_ID、完成状态、重要改动、真实测试证据、截图/录屏路径、已知风险、是否满足验收与唯一下一任务。完成本轮后立即停止。
