> 当前实现与验证情况：最终代码通过 `npm run typecheck`、`npm test`（70 个文件／865 项）、`npm run build` 和离线回放 benchmark（9/9 一致）。本轮门禁材料保护与跨局纪录修复后，制作／面板／AI NPC／Judge Mode 定向 E2E 为 13/13，shelter UI E2E 为 3/3；完整 Playwright 套件的 105/105 是这些最终改动之前的历史结果，本轮未重跑全套。生产构建有主 JS chunk 超过 500 kB 的非阻断提示。

## 已实现

- **受规则约束的 NPC 行动**：赠礼与维修都先产生结构化提案、运行 Validator，再由 executor 提交；拒绝路径不提交库存、关系、记忆或门禁变化。当前场景明确使用 `offline-fallback`，不是实时大模型或 Spark 推理。
- **赠礼—维修—门禁闭环**：赠礼可改变玩家与 NPC 库存、信任及持久记忆；低信任时拒绝。关闭门禁时，赠礼菜单隐藏维修材料，Validator 也会保护木材×2、胶带×1。达到信任 70 并带齐材料后，维修会实际消耗材料、打开故事门禁，随后允许从第 2 层进入第 3 层。
- **避免软锁**：第 2 层有独立 ID 的保证材料箱，固定提供木材×2、胶带×1。统一制作入口会把维修门配方材料保留到门禁打开；工作台和宿舍“修理”都不能消费预留库存，但有超额时可以花余量。旧存档只按本局门禁旗标、当前楼层或本局访问记录兼容；跨局最高楼层纪录不授予通行。
- **可审计导出**：Judge Mode 可展示实际赠礼／维修运行结果，并导出只包含允许字段的 JSON；相关实现见 `src/ai/competitionRunExport.ts` 与 `src/scenes/GameScene.ts`。
