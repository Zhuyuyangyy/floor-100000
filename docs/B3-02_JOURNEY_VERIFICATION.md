## 1. 验收原则的执行方式

你强调的两点,我用测试的写法本身来保证:

- **测试通过 ≠ 旅程成立。** 所以这个用例**没有任何传送、没有任何 `currentFloor` 直写、没有任何物品注入**。每一次换层都是「走到楼梯口 + 按真实 E」;每一次开箱都是「走到容器旁 + 按真实 E」;每一件拾取都是「从物品上走过去」自动触发。时钟也没有被 set—— including 等天黑,也是站着等真实时间流过。
- **代价是慢。** 全程约 7 公里走廊位移（130 px/s）+ 等到 20:00 的约 195 秒,单用例 4.9 分钟。这是证明闭环成立的诚实成本。

### 路线

```
1 层  醒来 → 喝掉 3 瓶起始净水（腾背包，顺带验证消耗品路径）
       → 上楼
2 层  穿堂而过 → 上楼
3 层  铁箱@800（废金属×3、撬棍×1）→ 木箱@480（木材×2、胶带×1）
       → 走过 x=160 自动捡起电池 → 上楼
4 层  落地即电箱@640（电线×2、滤芯×1、保险丝×1）→ 上楼
5 层  餐台@480（口粮×3、脏水×2）→ 下楼（本层无上楼口）
4 层  → 下楼
3 层  → 走过 x=1120 自动捡起布料 → 下楼
2 层  → 下楼
1 层  工作台@480：建成 照明灯 / 加固门 / 简易净水器（花掉 6 种材料）
       储物柜@160：首开得净水，再开不得（验证不重复领取）
       床@1120：等到 20:00 → 入睡
       重载页面 → 继续游戏 → 校验状态
```

## 3. 探索动机验证（用户要求第三节）

冻结设计 §5 要求「一昼夜需要至少数次有意义行动」。实测:

| 楼层 | 提供的探索收益 | 证据 |
|---|---|---|
| 2 | **交易**（唯一交易点，阿林/小周）。货架面包 50% 可能为空 | `npcs.ts:8`；`floorTemplates.ts:81` |
| 3 | 木材/胶带/废金属/撬棍——**加固门与净水器的唯一材料来源** | `floorTemplates.ts:100-120`；本测试实测取得并花掉 |
| 4 | 电线/滤芯/保险丝——**灯与净水器的唯一来源**；脏水×6 | `floorTemplates.ts:139-155`；本测试实测取得 |
| 5 | 口粮×3 + 脏水×2 + 面包×4，范围顶层的确定性补给 | `floorTemplates.ts:167-180` |
| 1 | 睡/制作/净水/升级；夜间事件免疫 | `EventSystem.ts:11`；`CraftingSystem.ts` |

**动机成立,且有因果链**：3/4 层的材料只能在家做成升级；不做升级,夜间宿舍暗度 0.6、脏水无法转化。本测试实测跑通「3/4 层取材 → 1 层建成三项升级」这条链,所以这不是纸面推断。

## 4. 本轮发现的阻断点与问题（按你的分类）

### 4.1 阻断点：无

旅程完整跑通,没有遇到必须修才能继续的缺陷。D9 的警告在正常流程中零误报。

### 4.2 发现一：12 格背包装不下一趟全搜（重要）

**现象**：第一次按「搜光所有容器」的路线跑到第 5 层时,`bread = 0`——包装满,补给架的面包被静默丢弃。

**机制**：`lootContainer` 在放不下时**整堆不动并回报 `full`,不丢物品**（`LootSystem.ts:45-60`），所以没有数据丢失,是设计正确的防丢。但**玩家侧只有一个 1.6 秒的闪现提示**（`GameScene.ts` 的 flash）。

**量化**： floors 1/3/4/5 全搜 + 3 件地面物品 = **15 种不同物品**,背包 12 格。差 3 格。

**影响**：玩家必须做选择。这本身是合理的生存游戏设计,不是 bug。但「闪过一行字」作为唯一反馈偏弱。

**最小修复建议（未实施,待你定）**：背包满时把提示改成持续显示（直到腾出格子),或在容器标签上标注「背包已满」。

### 4.3 发现二：「已探索」= 「拿过东西」,不是「来过」（重要）

**现象**：返回时 `visitedFloors[2]` 是 `undefined`——玩家穿过了第 2 层,但它不算已探索。

**机制**：`ensureVisit` 只被 `lootContainer` / `lootGround` 调用（`LootSystem.ts:10-17`）；`getFloorView` 只读不建。所以进入楼层不产生记录。

**影响**：塔楼总览的「已探索」着色（`TowerOverviewScene.getCells`）因此无法区分「路过」和「没去过」——两者都显示未探索。这与冻结设计 §2.6「楼层身份、已探索状态**必须持久化**」有偏差:当前语义是「在此搜刮过」。

**最小修复建议（未实施,待你定）**：在 `GameScene.changeFloor` 或 `getFloorView` 里对进入的楼层 `ensureVisit`,并把「已探索」的判定改为「有过进入记录」而非「有过搜刮记录」。

### 4.4 发现三：一趟往返只消耗约 4.5 游戏小时,离可入睡还有 9.75 小时

**现象**：06:00 出发,搜完 5 层、回家、做完三项升级,时钟才到约 10:15。睡眠要 20:00。

**量化**：全程约 7 km 位移 ≈ 54 真实秒；3 游戏分/真实秒 → 约 4.5 游戏小时。剩余 9.75 游戏小时 = 195 真实秒。

**影响**：单次探索用不掉一天。玩家当天还有大量空余时间,而当前除「再跑一趟」外无事可做（无委托、无交易循环目标、无建造队列）。这是 B3 之后「好不好玩」的核心问题,但**不是阻断点**。

**最小修复建议（未实施,属 B3-03/B5 范围）**：缩短单层走廊位移、或提高时钟速率、或引入需要多次往返的目标。

### 4.5 发现四：第 2 层货箱 50% 可能全空

`floorTemplates.ts:81` 的 `bread` 是 `probability: 0.5` 且无保证项。约一半种子下,第 2 层唯一的容器是空的,玩家在这一层得不到任何东西。不影响通关（材料在 3/4 层),但让第 2 层的探索收益不稳定。

## 8. 结论

**旅程成立**：从第 1 层醒来 → 走真实通路上到第 5 层 → 沿途拾取开箱 → 原路返回 → 在家把材料做成三项升级 → 等到天黑入睡 → 存档重载续上。全程无传送、无状态伪造,单次真实运行 4.9 分钟。

**探索有真实收益且因果闭合**：3/4 层的材料是家中升级的唯一来源,本测试实测走通并花掉。

**四个发现都不阻断旅程**,其中两个值得尽快处理：背包满反馈偏弱（§4.2)、「已探索」语义偏差（§4.3)。两者都是小改动,但要不要改、改哪种,等你定。
