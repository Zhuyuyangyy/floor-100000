## 1. 塔楼地图承诺了世界里没有的东西（最严重）

`TowerOverviewScene.floorContents` 读的是**掉落表**：

```ts
const names = c.loot.map((l) => getItem(l.itemId).displayName);
```

`c.loot` 是模板里的 `LootSpec[]`，**包含概率 roll**。所以第 1 层储物柜在每个种子上都广告「净水·布料」——包括种子 42，而它的 60% 布料 roll 是失败的，布料根本不在世界里。玩家取完之后也照样列着。

这个功能的注释写的是「把『去看看』变成『去拿滤芯』」。**名字错了，规划就错了。**

### 修法

按项目规则（核心规则可测试、Phaser 只渲染），把纯函数提到 [`LootSystem.describeFloorContents`](../src/systems/LootSystem.ts)，读**已解析的世界视图**（`getFloorView`：种子 roll 已应用、已取堆已移除）：

```ts
const view = getFloorView(state, floor);
for (const c of view.containers) {
  const looted = state.visitedFloors[floor]?.openedContainers.includes(c.id) ?? false;
  const unique = [...new Set(c.items.map((i) => getItem(i.itemId).displayName))];
  parts.push(`${c.label}${looted ? '(已取)' : ''}：${unique.join('·') || '空'}`);
}
```

一条修复同时解决两件事：只列真的 roll 出来的，取过的自动消失。

### 测试

`src/tests/lootSystem.test.ts` 新增 5 条，TDD 先行（先红：`describeFloorContents is not a function`）。包括「只列该种子真的 roll 出的」「取过之后不再提供」「地面物资取完也不再列」「无内容的楼层说未生成」。

**并且发现 `e2e/tower.spec.ts:225` 把 bug 锁死了**——它断言 `'储物柜：净水·布料'`。改成断言 `'储物柜：净水'` **且** `'布料'` 不可见。这是「测试通过不等于玩法成立」的又一例：测试一直在验证错误行为。

效果：楼层详情现在写「储物柜：净水」。

## 2. 第 4 层五个电箱只有两个能开（D7）

`drawMaintenance` 每个房间都放一个 `furn_fusebox`——**和可开启容器同一张美术包贴图**。所以第 4 层出现四个一模一样的详细电箱，只有 x=640 那个能交互。玩家无从分辨。

### 修法

装饰电箱改成 **Graphics 画的墙面机柜**：扁平、铆钉、通风百叶，没有危险标贴，剪影和真道具明显不同。真电箱保持美术包贴图 + 危险标贴 + 「电箱」标签。

不用新素材，且区分是一眼级的：**能开的是那个有贴图细节和标签的，其余是墙上的平板机柜。**

## 3. 结束画面的胜利文案描述的是已废弃规则（D8）

原文案：「在第 X 天 06:00 撑到了撤离评估点」——这是 v0.1 的第 8 天规则。而冻结设计（`GAME_DESIGN_LOCK.md`）里胜利条件是**抵达第 100000 层**（B8）。今天唯一能把 `status` 置为 `won` 的是 `isLegacyVictory()`，且它被 `?devwin=1` 夹具挡着——**正常玩法永远看不到胜利画面**。

### 修法

让它说真话，并顺便告诉玩家真正的目标：

```
你活了下来
旧版第 8 天阈值 · ?devwin=1 夹具
存活 8 天 · 正式胜利条件为抵达第 100000 层
按 回车 重新开始
```

加长的那行经截图确认仍在横幅内、未溢出，且继续避开左侧图标（横幅图标的既有约束）。

### 顺带修掉一个满载才现形的测试 bug

`events.spec.ts` 的「巡游体可躲避」在满载跑时会失败（单独跑三次都过）。我第一版诊断错了——以为是 Phaser `destroy()` 延迟，加了 5 秒等待，**照样失败**。错误上下文给出真相：

```
Expected: 100
Received: 92
```

玩家挨了一下 8 点。根因在测试自己的设置：`setX(page, 40)` 把玩家传送到 x=40，而巡游体刷新在玩家对端——玩家当时在 `ENTRY_X`(640)，所以它刷在 x=48，**正好是上楼口**。传送把玩家塞到它脸上，负载下截图加读状态拖过它追过来的时间，就打中了。游戏行为是对的（半夜站在巡游体旁就是会挨打），是测试把自己送进了危险区。

修法：改从**下楼口**（x=1240）逃，那是远离它的方向。撤掉了基于误诊的等待。
