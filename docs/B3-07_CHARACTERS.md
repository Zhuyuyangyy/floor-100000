# B3-07 — 角色像素自制 + 暴露出的三套尺度

- 里程碑：M1 可玩原型
- 日期：2026-10-28
- 分支：`feat/tower-zoom-b2`
- 起因：`char/` 里 171 个切片是 139 种尺寸的独立立绘，没有对照表，识别成本高且与项目调色板无关。项目负责人决定由我程序化自制。

---

## 1. 做了什么

新增 [`tools/build-characters.mjs`](../tools/build-characters.mjs)，用项目自己的 `tools/png.mjs`（无 Pillow/OpenCV，本机也无 Python）画出 4 个角色，输出到 `public/assets/artpack/char-*.png`：

| 贴图键 | 文件 | 辨识特征 |
|---|---|---|
| `player` | `char-player.png` | 青色外套、深色短发、右肩背包、腰间胶带 |
| `npc_alin` | `char-alin.png` | 蓝色工作服、帽子+帽檐、工具带挂两件工具、身板更宽（躯干 13） |
| `npc_xiaozhou` | `char-xiaozhou.png` | 棕色围裙、长发披肩、身板更窄（躯干 10）、腋下面包 |
| `wanderer` | `char-wanderer.png` | 暗红、驼背（头前移 3px）、手臂过膝、双腿收成尖角、红眼 |

替换掉 `pixelArt.ts` 里的 `drawHumanoid`——那原本是**同一个 16×24 剪影涂四种颜色**，所以玩家、两个邻居和夜间威胁长得一模一样。

按生产规范落的硬约束：

- **一块固定画布** 32×48，四个角色共用
- **统一脚底基线**：所有靴子都结束在第 47 行，换帧不跳位
- **一套共享调色板**：项目六色（`05_ART_GUIDE.md` §2）加派生明暗，肤色刻意去饱和以贴合墙体的末日色调
- **只用硬边**：没有抗锯齿、没有平滑插值，每格一色
- **RGBA 透明**，不是白底假透明

自检手段是 `--dump` 把每个精灵打成 ASCII（`.`)` 表示透明），加一张 4× 接触表 [`char-contact.png`](../e2e/screenshots/char-contact.png)。

## 2. 过程中抓到的两个真 bug

都是「静默失败」型，值得记：

**背包根本没画出来。** `body()` 没把 `torsoW` 放进返回值，背包的 x 算成 NaN，而 Buffer 用 NaN 索引是静默无操作——ASCII 里看得见手臂和带子，唯独背包不存在。修法是补返回值。

**阿林和小周没有头。** 它们的 `body()` 调用没传 `skin`，而 `set()` 里 `!c` 的守卫让未定义颜色**静默跳过每一个像素**——结果轮廓线还在，脸是空的，只剩两个眼点漂着。玩家传了所以有脸。修法是在 `body` 里给肤色默认值，而不是要求每个角色都传。

这两个是同一种病：**一个静默跳过的守卫，让缺参数表现为「少画了一块」而不是报错。**

## 4. 但是：角色把场景里三套互不相关的尺度同时暴露了

这是本轮真正的发现，比角色本身重要。

| 尺度 | 属于谁 |
|---|---|
| **16px** | `tile_wall` / `tile_floor` / `tile_door` / `tile_window`（全是程序化 16×16 图） |
| **48px** | 角色（本次新增） |
| **80px** | 全部家具（`FURNITURE_HEIGHT = 80`，美术包道具统一缩到这个高度） |

玩家原来是 16×24，和门一样高，所以这套不一致看不出来。角色一到 48px，三套尺度的冲突立刻可见：

- **货箱比人高 66%。** [`32-floor-3-storage.png`](../e2e/screenshots/32-floor-3-storage.png) 里玩家站在两个货箱堆之间，单个货箱 80px、人 48px。箱子比人高，读起来是错的。
- **门比人矮。** `tile_door` 是 16×16 的图，人 48px。门应该约等于人的 1.8 倍高，实际只有人的 1/3。 [`31-floor-2-worker-dorms.png`](../e2e/screenshots/31-floor-2-worker-dorms.png) 里三个角色旁边的门像墙上的小配件。
- 工作台那张还算过得去，因为 `furn_workbench` 的 80px 里包含墙上工具板。

**这和你最早指出的「小格子和贴图格格不入」是同一个根因**：程序化的 16px 体系 and 美术包的 80px 体系从来没见过面，角色只是让冲突从「背景」蔓延到了「可交互物体」。

### 为什么不能靠改一个常数解决

`FURNITURE_HEIGHT = 80` 当初选 80 是为了让道具留在墙面可用高度内、且不会一个道具是另一个的两倍高而像贴纸——**那个推理在玩家只有 16px 时成立**（道具是人的 5 倍），现在不成立。

但把它调小要连带动一堆写死的坐标，`corridors.ts` 里全是按 80px 道具调过的：

| 位置 | 值 |
|---|---|
| 壁灯光池 | `floorY - 150` |
| 配电箱 | y = 176 |
| 水箱 | `roomX + 300` |
| 后墙货架顶 | `floorY - 74` |
| 货箱堆叠间距 | 取自贴图实际高度 |

门和窗要变成合理高度等于**重画** `tile_door` / `tile_window`——而那正是卡在你这边的背景工作。

## 5. 三个选项（需项目负责人定）

| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 家具降到 ~56px** | 改 `FURNITURE_HEIGHT` 重跑 `build-artpack`，再按比例重调 `corridors.ts` 那五处坐标 | 中。一次性能把「箱子比人高」修掉，但门还是 16px |
| **B. 角色涨到 ~64–72px** | 改画布重画，四个角色等比放大 | 小。但角色会 dominate 画面，且 640×360 里 72px 的人偏大 |
| **C. 连同门/窗/背景一起重做** | 按之前给的背景规格，一次把 16px 体系换成大尺度 | 大，且卡在你提供素材 |

**我建议 A + 单独重画门**：家具降到 56px 让箱子≈人的 1.17 倍，门重画成 ~56px（约人高）是两张小图、不依赖外部素材、我可以直接做。B 会让角色比门还高，问题更怪。
