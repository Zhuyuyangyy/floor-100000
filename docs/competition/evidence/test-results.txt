8) 过程中出现的两次「假红」——如实记录，不算门禁结果
================================================================================
这两次都是**我自己的调用方式错误**，不是仓库缺陷，也不是被测代码的问题。
把它们写进来，是因为：如果不写，下一个人照抄同样的命令，会得到一份
「444 个测试失败」的报告，然后去追一个不存在的 bug。

--------------------------------------------------------------------------------
8.1 第一次：vitest 收集了 3247 个测试文件，444 failed
--------------------------------------------------------------------------------
  起因：用 `npm --prefix <repo> exec -- vitest run` 调用。
  **npm exec --prefix 不会把工作目录切到 --prefix 指向的目录**，
  于是 vitest 的工作目录停在会话根目录 `D:\ZYY_Inovation\game`，
  在那里按默认 include 递归收集，扫进了：
    - `tmp/qa-evidence/split-step*/baseline-src/**`（另一个 agent 的基线源码副本）
    - `D:\ZYY_Inovation\game\agent-worktrees\gameplay\src\**`（另一个 agent 的 worktree）
  结果：
    Test Files  3247 failed | 4467 passed | 12 skipped (7726)
         Tests  444 failed | 84008 passed | 182 skipped (84634)
      Duration  781.88s
  那 444 个 failed **全部**在上述副本/worktree 里，不在 `src/` 或 `server/`。
  同一份代码用正确方式跑（见第 2 节）只要 2.65 s，且 0 failed。

  同一次链里还暴露了两个真实情况，一并记录：
    · `npm run build` 当时 exit 1，两条 TS6133 未使用符号
      （`src/scenes/GameScene.ts:187 NPC_AUTONOMY_ACTOR`、
        `src/scenes/GameScene.ts:4217 updateNpcAutonomy`）——
      这是 **A3 正在进行的自主 tick 在途改动**，未提交，几分钟后即消失。
    · `npm run test:collection` 当时 exit 0，但它读的是 2026-11-26 20:36
      那次的旧 `output/vitest-report.json`——**这个门禁必须在 test:ci 之后跑**，
      否则它校验的是旧报告。正确顺序见第 3、4 节。

--------------------------------------------------------------------------------
8.2 第二次：playwright 报「config 不存在」
--------------------------------------------------------------------------------
  起因：同样用了 `npm exec --prefix`，工作目录停在会话根目录，
  于是相对路径 `playwright.public.config.ts` 解析到了
  `D:\ZYY_Inovation\game\playwright.public.config.ts`（不存在）。
  报错原文：
    Error: D:\ZYY_Inovation\game\playwright.public.config.ts does not exist
  修法：给 `-c` 传**绝对路径**。修好后 3/3 通过（见第 6 节）。

--------------------------------------------------------------------------------
8.3 给下一个跑门禁的人（以及 CI）
--------------------------------------------------------------------------------
  · 用 `npm --prefix <dir> run <script>`；**不要**用 `npm --prefix <dir> exec -- <cmd>`。
  · `test:collection` 必须紧跟在 `test:ci` 之后跑，否则校验的是旧报告。
  · 这个仓库没有 `vitest.workspace` 之类的边界文件，而
    `D:\ZYY_Inovation\game\` 下面同时躺着多个 agent 的 worktree——
    一旦工作目录跑到仓库外面，vitest 会把它们一起收进来。
    建议 A11 在 CI 里显式指定工作目录，或加一条 workspace 边界。
