## 审查基线必须关闭的问题（历史记录）

### 1. 攀爬时角色会被相机裁切：基线三种子复现，2026-11-22 已修复

[纵向 bounds](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/scenes/GameScene.ts#L591-L600) 在审查基线的首层上楼和第五层下楼时不能覆盖完整角色路径。只读帧采样确认，第 1 层上楼期间角色上端超出视口，第 5 层下楼末段角色几乎完全出框，随后落地重绘才恢复；这是当时的结果，不代表当前修复后的行为。

2026-11-22 后续改动已按最小方案关闭此项：只在攀爬期间按路径、角色高度与 HUD 安全留白临时扩展纵向边界，落地恢复普通楼层 bounds。Seed 42 的真实键盘路线 `1→2→3→4→5→4` 专项 E2E 通过；第 1 层上楼与第 5 层下楼端点角色均处于 HUD 安全区，且落地后的 `camera.getBounds()` 与普通中层边界相等。详见 [`B3-19_NATURAL_STAIRS.md`](B3-19_NATURAL_STAIRS.md)。

### 2. F 与旧攀爬可能叠加提交：代码路径确认，资金充足实测尚缺

[F 的绑定与 guard](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/scenes/GameScene.ts#L2667-L2710) 只做同帧去重，[近路入口](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/scenes/GameScene.ts#L2963-L2995) 没有 `stairClimb` 互斥。`clearFloor` 不清掉旧攀爬，而 [落地提交](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/systems/FloorSystem.ts#L105-L124) 不核验 `traversal.from`。

因此按代码，在 Seed 42、D1、第 2 层且至少有 114 金时，E 开始上楼后立刻按 F，可先付费到 4 层，再由旧攀爬多提交到 5 层。这是基线已存在的状态竞态，并非本轮两个提交新引入；本轮没有通过注入金币去冒充真实复现。应先阻止攀爬中的 F，再为陈旧 traversal 增加状态校验及回归测试，不改变定价公式。

### 3. F 显示价格与实际需求不一致：真实输入已复现

[提示](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/scenes/GameScene.ts#L3540-L3543) 用原始 skip 报价，[执行](https://github.com/Zhuyuyangyy/floor-100000/blob/ea8538f/src/scenes/GameScene.ts#L2976-L2980) 则先按剩余楼层截断。Seed 42、D1、第 4 层，井口显示 **128 金**，按 F 后却提示实际需要 **108 金**。Seed 1、2026 同层分别显示 138 / 118 金，实际都需要 108 金；Seed 2026 第 2 层也显示 134、实际需要 124。

资金不足时，本轮均验证金币、楼层和近路次数不变。成功付费、落点与攀爬中 F 的资金充足真实流程仍未验证，不能据此标记全部 F 验收通过。这项报价问题同样是基线已有；提示与执行应共用截断后的 skip，不重做经济系统。

## 后续复查：存档失败提示重复（2026-11-22）

**根因**：HUD 的 `flash()` 1.6 秒后清除提示，而自动存档每 5 个游戏分钟尝试一次（游戏时钟每真实秒推进 3 分钟，约每 1.67 秒一次）。配额持续失败时，每次失败都使计数增加并重新启动同一提示，所以间隔中的短暂空隙很容易被浏览器轮询错过。

**修复**：存档层仍记录每次失败，但额外按“连续失败期”计数；第一次失败提醒一次，失败重试不重复触发提示，任意一次写入成功后清除失败期，后续再失败则重新提醒。没有更改写入尝试、存档结构、游戏规则或存储位置。

**验证**：
- 修复前重复运行 `npx playwright test e2e/saveFailure.spec.ts --workers=1 --repeat-each=5`：10 次中 9 次通过、1 次复现“提示未在 10 秒内消失”。
- 修复后 `npx vitest run src/tests/save.test.ts`：36/36；`npm run test`：58 个文件、757/757；`npm run typecheck`：通过；`npm run build`：通过，保留既有大型 JS bundle 警告。
- 修复后 `npx playwright test e2e/saveFailure.spec.ts --workers=1 --repeat-each=3 --reporter=line`：6/6 通过；已保存失败提示可视截图到本地忽略文件 `output/save-failure-warning.png` 并肉眼检查。
- **本轮没有重跑 93 项全量 E2E**。最近一次全量结果仍是修复前 90/93；其余两项旧失败的当前状态未知。
