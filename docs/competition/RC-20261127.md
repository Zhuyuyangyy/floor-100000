## 3. 凭什么说它可用（三份实测证据）

### 3.1 带凭证的线上验收：40 条判据，**39 通过 / 1 FAIL**

- 证据：`artifacts/online-verify/`（六份，`hasToken:true` / `forceWrite:false`）
- 记忆段 **8 条全绿**（三组对照全成立、极性总增益 2.00 ≥ 1.50、锚点回响命中 4 次、
  对照组零锚点成立、weight 专项极性差 1.50 ≥ 1.00 且单调成立）
- **唯一那条 FAIL 是判据假阳性**：路径穿越载荷在线上拿到的是**网关自己的 400 错误页**
  （225 B，Tengine），逐字查过不含 `NPC_API_KEY`、不含 `/api/npc/decide`、不含源码；
  判据只比「与基线不同」，把「400 错误页 vs 200 首页」读成了泄漏。**产品没有泄漏。**

### 3.2 线上公开 E2E：**2 / 2 通过**（3.3 min）

```
✓ 线上 · 黄金路线 0:00–10:00：开局 → 2 楼送礼 → 修门 → 上 3 层出第 1 章结算卡
✓ 线上 · BLOCKER-01：模型不可用时修门不能变成一条没有下一步的死路
```

第二条修前是**红的**：模型不可达时「阿林不接活」，玩家材料凑齐、信任 78.2（门槛 70）
按下维修门却什么都不发生，面板还只给一句「校验拒绝｜未改变」。
根因是「模型挂了」与「模型说不动」被压成同一个信号（null），导致 fallback 被禁止、
「模型不可用时玩家仍能玩完」这条护栏从未执行。已修（`868d6b6`）：模型不可达改为抛异常，
运行时记 `proposal_error` 并调用规则兜底，来源如实标 `offline-fallback`。
**判据一条没动。**

## 5. 出事怎么退回去

**回滚包 = 创空间仓库 master 的上一个提交 + 一次重新部署。**

```bash
# 1) 回到上一个已知可用的产物（示例：当前是 38a223f → 退到 728fa12）
cd <创空间仓库 clone>
git log --oneline -5 master            # 找到要退到的那个提交
git reset --hard <目标提交>             # 本地切到那个提交
git push origin master                 # 强制推（创空间仓库允许）
# 2) 触发重新部署
curl -X POST "https://modelscope.cn/openapi/v1/studios/a1578804454/floor-100000/deploy" \
  -H "Authorization: Bearer $MODELSCOPE_API_KEY"
# 3) 验活
curl -s "https://a1578804454-floor-100000.ms.show/healthz" -A "Mozilla/5.0"
```

- **已知可回退的产物**：`assets/index-Dzve_6tz.js`（16:58 那次带凭证验收测的就是它）、
  `assets/index-TkYEZy4I.js`（当前）。
- **代码侧回退**：发布线上的任意提交都有 tag 或 SHA；`git revert` 落在发布线即可。
  本候选有 tag `rc-20261127-a`。
- **不需要回滚的情况**：平台重建容器时若新产物起不来，平台会自动回退到上一次成功镜像，
  `status` 回到 `Running`；可用 `assets/index-*.js` 文件名比对确认线上跑的是哪一版。
