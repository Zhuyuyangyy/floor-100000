# 跨模块接口约定

## IF-01 导航与楼梯（AG-02 → AG-03 / AG-01）

- 权威楼层变化仍由现有 FloorSystem 处理。
- 楼梯动画期间只更新视觉位置；落地时才提交 currentFloor、访问记录和存档。
- 陈旧 traversal 的 from 必须与当前楼层一致，否则拒绝提交。
- 快捷近路的 skip、price、目标楼层由同一个纯函数报价结果计算；提示和扣费不得各自重复公式。
- 攀爬中 E/F 必须互斥；不得出现旧 traversal 在付费跳跃后再次提交。
- AG-02 提供纯函数和代码修复；AG-03 通过真实键盘 E2E 验收。

## IF-02 世界生成（AG-04 → AG-01）

- 首轮输出独立 FloorDescriptor / SectorProfile 契约，不修改 GameState。
- 100 个区段，每区段 1000 层；总层数 100000。
- 必须按需生成，不得预分配十万 Floor 对象。
- 相同 worldSeed + floorId 结果稳定；不同 seed 可变化但遵守同一阶层曲线。
- AG-04 提交 Schema 和测试，AG-01 审核后再安排运行时接入。

## IF-03 经济模拟（AG-05 → AG-04 / AG-01）

- 经济模拟读取现有物品、配方、掉落和交易规则；现有生产数值只读。
- 模拟结果区分“当前系统实测/模拟”与“B5 提案假设”。
- 不在本轮直接修改物品价值、掉落率、饥渴消耗或制作配方。
- 输出资源曲线、资源枯竭/通胀、背包瓶颈和基地升级可达性。

## IF-04 NPC 库存（AG-06 → AG-01）

- AI 仍只提出行动建议，规则执行器仍是唯一裁决方。
- NPC 库存必须有上限、稳定 itemId、数量守恒和原子交易。
- 首轮实现独立可序列化的数据模块，不写入 GameState、不接入运行时。
- AG-06 提交状态结构、迁移/持久化建议和单元测试；AG-01 再决定存档字段与接线。

## IF-05 美术资产（AG-07 → AG-09 / AG-08）

- 素材库为设定/候选资产；运行时由 public/assets 加载。
- 首轮建立清单和导入映射，不移动或覆盖原始素材。
- 背景切片尺寸、透明通道、动画帧数和授权来源必须记录。
- AG-09 负责渲染接入建议；AG-08 负责 UI 资产消费，不得同时编辑资产源。

## IF-06 UI（AG-08 → AG-01）

- UI 只显示权威状态并发送输入意图，不自行执行游戏规则。
- 保留键盘导航、焦点可见、文字无遮挡和现有 Ark Pixel 字体。
- 不修改 GameScene 的背包/交易核心逻辑；涉及 GameScene 的 UI 接线另开任务。

## IF-07 渲染性能（AG-09 → AG-07 / AG-01）

- 先测量，再优化；必须报告设备、浏览器、分辨率、帧率和对象/绘制调用估算。
- 保持像素硬边、场景深度和动画时序。
- 不为追求性能牺牲可见的场景内容；不改 GameScene。

## IF-08 首章叙事（AG-10 → AG-01 / AG-06）

- 主角是普通底层居民，从第1层床铺醒来，不是天选之人。
- 阿林和小周是邻居，不是无人格商店。
- 当前完整主线任务链尚未实现；文档提案必须标为 Proposed。
- 第一章设计聚焦第1–5层；宏观十万层与四条终局路线逐步揭示，不在开局倾倒设定。
- 任务/Flag 设计不得假设运行时接口已经存在。
