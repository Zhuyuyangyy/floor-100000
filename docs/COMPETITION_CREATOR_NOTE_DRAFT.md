## 1. 创意与玩法

《第100000层：末日宿舍》是一款 Phaser 浏览器横版生存游戏。玩家从塔楼底层的宿舍醒来，在有限背包和逐渐消耗的饥饿、口渴、精力之间做取舍：出门探索、搜刮物资、与邻居交易，再赶回宿舍制作升级、休息并开始新的一天。当前仓库明确标注的可玩范围是第 1 至第 5 层；“第 100000 层”是长期设定目标，不代表目前已有十万层内容或已完成的登顶结局。

当前可验证的核心旅程是：从宿舍出发，探索并搜集首五层资源，返回工作台制作升级，在床边过夜后继续游戏。第 2 层有阿林与小周的对话/交易；默认 NPC 回应标为“本地行为 AI · 规则驱动”。它是确定性的规则人格脑，不是现场大模型生成或自由聊天。详细边界见 [`COMPETITION_AI_DEMO.md`](COMPETITION_AI_DEMO.md)。

【作者补充：用自己的试玩描述最有趣的取舍、希望玩家感受到的主题，以及真人试玩反馈；目前仓库里的自动化测试不能代替“玩家觉得好不好玩”的证据。】

## 2. 创作过程

从仓库可以确认：项目使用 Phaser 4.2.1、TypeScript 和 Vite；游戏规则主要位于可独立测试的逻辑模块，Phaser 负责场景呈现与输入。首五层的内容包含生存状态、楼层探索、容器搜刮、背包、NPC 交易、宿舍制作、睡眠与浏览器本地存档。近期文档记录了竖屏视口、窄屏 HUD 和触控按钮适配，以及首五层旅程的自动化验证。

游戏内 NPC 采用“提议—校验—执行”的边界：AI 接口给出行动建议，规则执行器检查合法性，游戏再走既有规则；它不能直接修改生存数值或越过交易、背包、战斗规则。默认公开试玩使用离线确定性规则脑。可选的本地 Ollama 路径必须由开发者显式配置，不能据此声称公开版在调用模型。

## 4. 问题与解决

一个可核实的问题是：把原有横屏游戏直接缩进手机竖屏，会让可操作区域过窄。项目采用 Phaser 的 ENVELOP 显示方式，并将游戏相机调整为居中的窄视口；菜单、HUD、背包和触控按钮也按窄屏布局。触控移动沿用已有移动规则，并在松手、取消、失焦或切到后台时清除方向，避免角色持续移动。

仓库文档记录了 `npm run typecheck`、762 项单元测试、构建、竖屏触控 E2E 4/4、桌面界面回归 13/13，以及真实走过第 1–5 层、回家睡觉的旅程 E2E 1/1。完整五层旅程的自动化路线使用键盘验证；首层触控交互已测，但完整五层触控旅程尚未单独验证。构建会提示 JavaScript 主包约 1.61 MB，超过 500 KB 的建议值，但构建通过。以上是自动化验证，不是人工试玩或 AI 工具使用凭证。

【作者补充：如有真人试玩，请记下设备/浏览器、参与人数、实际反馈及修正前后对比；没有就不声称做过。】

## 5. 经验总结

目前的实践经验是把游戏规则与画面输入分开，让生存、交易、背包等规则可独立测试；NPC 的行动建议也必须经过规则校验。这样可以明确说明默认体验真正做了什么，也能让不启用本地模型时游戏仍可游玩。

下一步适合优先补齐公开试玩部署、完整录屏和真人试玩反馈，并在投稿前确认手机地图等未覆盖路径。AI 相关描述应以所提交版本实际运行方式为准：离线规则回应就称规则驱动，不把可选 Ollama 配置写成已部署服务，也不把代码中存在的接口写成已经使用某个外部模型。
