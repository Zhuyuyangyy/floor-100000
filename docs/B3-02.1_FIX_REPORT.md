## 2. 背包满常驻提示（§4.2）

### 为什么原来的形状不对

背包**会一直满着**，直到玩家花掉东西。对这样一种持续状态，「告诉你一次然后安静 1.6 秒」是错的形状：玩家在第 3 层塞满背包，走到第 4 层时屏幕上什么都没有，下一层的补给被留在原处，读起来就是 bug。

原来的 `lootContainer` 行为本身是对的（整堆不动、回报 `full`、不丢不吞），要改的只是**玩家侧的可见性**。

### 改动

- `src/systems/InventorySystem.ts` — 新增纯函数 `isBagFull(inv)`：`slots.length >= slotCount`。规则只有一条，不该由场景各自猜。
- `src/scenes/GameScene.ts`
  - HUD 新增 `bagFullText`（`y=86`，居中，红色 `#e8907c`，默认隐藏）。放在闪现文字（`y=60`）下方，两者可同屏不重叠。
  - `refreshBagFullWarning()`：每帧比对，**只在状态翻转时** `setVisible`。
  - 调用点放在 `update()` 里、面板 early-return **之前**——背包满最要紧的时刻正是玩家打开背包找东西用的那一刻。

### 两种提示的分工

| | 内容 | 生命周期 |
|---|---|---|
| 闪现 | `背包已满，剩余留在容器` | 1.6 秒，回答「刚才发生了什么」 |
| 常驻 | `背包已满 · 使用、制作或交易腾出格子，否则搜刮会留在原处` | 直到腾出格子，回答「现在的状态是什么」 |

e2e 用 `否则搜刮会留在原处` 作为断言标记，**故意不与闪现文案共用子串**，否则残留的闪现会让断言假通过。

### 验证（`e2e/bagFullWarning.spec.ts`，51.5 秒）

真实走路、真实塞满，没有改背包、没有改 `slotCount`：

```
1层(3/12) → 2层 → 3层 铁箱+木箱 → 4层 电箱(11/12) → 储水罐(12/12)
```

- 起点 3/12：警告不出现
- 电箱后 11/12：警告仍不出现（差一格就是不满）
- 储水罐后 12/12：警告自动出现
- **等 3 秒后仍在**（远超旧的 1600ms）—— 这是本次修复的重点
- 打开背包后仍在（`refreshBagFullWarning` 在面板 early-return 之前）
- 喝掉 3 瓶净水（**必须喝完一堆才腾出格子**，喝 1 瓶不腾）→ 11/12 → 警告自行消失
- 下到 1 层开储物柜，拿到保证掉落的净水 → 12/12 → 警告再次出现（证明不是一次性闩锁）

背包数量的确定性：无论 `crate_metal` 的 60% 电池有没有掉，最终都是 12 格——因为箱子电池和地面电池是同一种物品、共占一格。实跑 seed=42 时电池没有从箱子掉，只从 x=160 地面捡到 1 个。

单测（`src/tests/inventorySystem.test.ts`，4 例）：有空槽为 false / 满槽为 true / 只看槽数不看堆叠数 / 消耗后回到 false。

## 3. 楼层访问记录（§4.3）

### 问题

`ensureVisit` 只被 `lootContainer` / `lootGround` 调用，`getFloorView` 只读不建。所以**穿过一层不留任何记录**，塔楼总览的「已探索」着色分不出「路过」和「没去过」——两者都画成未探索。这与冻结设计 §2.6「楼层身份、已探索状态与重要世界变化必须持久化」直接冲突。

### 改动

- `src/systems/LootSystem.ts` — `ensureVisit` 改名为 `recordFloorVisit` 并导出（两个内部调用点同步改名）。
- `src/scenes/GameScene.ts` — 在 `drawFloor()` 开头调用。

**为什么是 `drawFloor()`**：它是玩家「到达一个楼层」的唯一入口——新游戏、继续游戏、`?devfloor=` 开发入口、以及每一次走楼梯，全都要经过它。一处覆盖全部路径，不需要在每个入口各写一遍。

- `changeFloor()` 里把 `saveToStorage` 移到 `drawFloor()` **之后**：换层的存档现在包含刚踏上的这层，否则要等下一次自动存档才落盘。

### 语义

「已探索」= **来过**。

「拿过东西」并没有丢：`openedContainers` / `lootedItems` 仍然分别记录，塔楼楼层详情面板的 `(已取)` 标记正是读它们。所以数据里「路过」和「搜刮过」依然可区分，**没有新增字段**。

### 代价（如实记录）

`visitedFloors` 现在按**进入过的楼层**增长，而不是按**搜刮过的楼层**增长。仍以玩家真实走过的楼层为上界；每条形如 `{openedContainers:[], lootedItems:[], unlockedDoors:[], localEvents:[]}`，约 90 字节，在玩家真的动手之前不增长。`SaveSystem.validateGameState` 已校验这 4 个字符串数组，空数组通过。

### 验证

单测（`src/tests/lootSystem.test.ts`，5 例）：走过即记录 / 幂等且不覆盖已有搜刮记录（返回同一对象）/ 走过与搜刮过可区分 / 存档 round-trip 后仍在 / 记录访问不会重新生成 loot。

`e2e/survivalJourney.spec.ts` 三处断言随语义更新：
- 醒来时 `visitedFloors` 不再是 `{}`，而是 `['1']`——玩家站着的那层就是已探索
- 返回时 2/3/4/5 层全部有记录（第 2 层虽然只是穿过）
- 重载后记录数 `>= 5`

## 4. 顺带确认（未改）

- `TowerOverviewScene` 的 `explored` 判定读 `visitedFloors[floor] !== undefined`，自动跟随新语义，无需改动；`openedContainers.includes(...)` 对空数组返回 false，详情面板的「已取」标记不受影响。
- `TowerNav.accessOf` 的 `highestUnlocked` 取 `max(currentFloor, visitedFloors 最高键)`。新游戏记下第 1 层不影响任何判定（`currentFloor` 本来就是 1）；`?devfloor=5` 开局记下第 5 层也不改变结果。
