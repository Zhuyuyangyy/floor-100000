## 1. 名场面 A —— 记忆改变行为（当前**已有线上证据**）

**这是总控计划 §11 里要求的第一件事，也是本次线上证据最扎实的一段。**

### 建议时间码骨架

| 时间码 | 内容 | 画面必须出现 | 对应证据 |
|---|---|---|---|
| `00:00–00:20` | 交代当前处境：这是第 100000 层，面前这位 NPC 是阿林 | HUD 显示楼层、任务目标、背包 | 正常入口 |
| `00:20–01:00` | **第一次**向阿林提出同一个请求（例如「帮我看看这道门」） | 阿林的回应是**戒备/拒绝**；HUD 里关系值偏低；来源标签 `model` | 记忆段对照组的 `refuse` 样本 |
| `01:00–01:40` | 说明玩家与阿林的**历史**（这一步必须有可解释的历史来源：玩家曾失约/被拒，或曾受助） | 玩家侧能指认那次交互发生在哪里 | `memory-evidence.json` 的 `memorySent`（有 `day`/`kind`/`summary`/`weight`） |
| `01:40–02:20` | **第二次**向阿林提出**完全相同**的请求 | 阿林的回应**换了动作类型**（从拒绝变成愿意帮忙/提供帮助）；来源标签仍是 `model` | 对照组 vs 记忆组的意图分布 |
| `02:20–02:40` | 收尾：点开对话记录/判定面板，指出两轮的唯一变量是「有没有带那段记忆」 | 屏幕上能看到两轮的请求文本一致 | 判据「同一请求因历史不同产生可解释的不同结果」 |

### 判据（录完必须逐条满足）

1. **两轮的请求文本必须逐字相同**——不同就作废（变量必须是记忆，不是措辞）。
2. **动作类型必须变**（`refuse` → `dialogue`/帮忙类），不只是台词措辞变。
3. 两轮都必须是 `decisionSource = model`。
4. 画面上必须能指出「那段记忆从哪来」（哪一天、哪件事），不能是凭空的一句设定。

### 线上已有的硬数字（可直接念，画面不必重复展示）

- 三组对照全部成立，**极性总增益 2.00 ≥ 1.50**；每组固定 **5 轮**，不早停。
  - 「失约 vs 守约」：对照组 5/5 `refuse`（极性 −1.00），记忆组 5/5 `dialogue`（极性 0.00），差 1.00。
  - 「被拒 vs 获赠」：对照组 5/5 `refuse`（极性 −1.00），记忆组 5/5 `dialogue`（极性 0.00），差 1.00。
  - 「无记忆 vs 受助」：两组极性都是 0.00，靠**锚点回响**区分（锚点命中 4 次，对照组 0 次）。
- **锚点回响命中 4 次、对照组零锚点成立**——这是「模型真的读到了记忆正文」的直接证据。
- 联合判据的假阳性率（随机意图、完全不读记忆的桩，30 万次模拟）约 **0.0043%**。

## 2. 名场面 B —— 规则拒绝后重新规划（**机制已实现，但线上证据只到「改口」这一步**）

### 建议时间码骨架

| 时间码 | 内容 | 画面必须出现 | 对应证据 |
|---|---|---|---|
| `00:00–00:20` | 交代处境：玩家想修一道门，但**材料不齐** | HUD/背包里能看见缺哪一样（例如缺胶带） | 正常入口 |
| `00:20–01:00` | 向阿林提出维修请求 | 阿林**没有假装能修**，而是**改口要材料**（`request_help` + `itemId` + `quantity`） | 判据「缺料时不声称能直接修（或改口要材料）」，线上实测返回 `{"intent":"request_help","itemId":"tape","quantity":1,"utterance":"还缺一卷胶带，你能找到吗？"}` |
| `01:00–01:40` | 玩家去拿到那件材料，回来再提一次 | 这次动作**变了**（真的开始修），且**库存/世界状态发生可见差量** | 判据「维修任务来源是模型」、`repair_gate` 契约 |
| `01:40–02:10` | 打开判定面板 / 日志 | 能看到**规则层**的判定（拒绝原因、是否进入重规划、来源标签） | `replan` / `decisionSource` 字段 |

### 判据

1. **必须出现一次「模型想修 → 规则/状态不允许 → 模型改口」**。只要一直顺畅，就说明这段没拍到关键。
2. 改口后**不能凭空成功**——缺的东西必须真的被拿到。
3. 必须能看到**状态差量**（材料从玩家/居民库存里真的扣掉、门/线路状态真的变了）。
4. 全程 `decisionSource = model`。

### 🔴 本段当前**没有**线上证据的地方（录制前必须知道）

- **有界重规划机制确实存在**：`src/ai/competitionRuntime.ts:107-131` 的 `runCompetitionStep` 是
  「最多 N 次尝试（默认 2，硬上限 3），任一次被拒或执行失败都会把反馈喂回去，下一次**重新采集观察**再走一遍
  目标选择 → 规划 → 提案 → 校验」；拒绝原因通过 `previousRejectedReason`
  （`src/scenes/GameScene.ts:4090/4264` → `server/npc-proxy.mjs:318` 渲进提示词）。
- **但已记录的 trace 里 `replan.attempted` 是 `false`**（`replan: { attempted: false, attempt: 0, reason: 'none' }`）。
- 线上能证明的只到**「缺料时模型改口要材料」**这一层（判据 16）。
- **所以**：录这一段时，**必须真的触发一次拒绝**，让面板上出现 `replan.attempted = true`（或等价的重规划记录），
  否则这一段只是「模型说了一句要材料」，证明不了「重规划」。

## 4. 三个名场面共用的一条：来源标签必须可见
