# 模块接口与协作契约（Wave 0 草案）

> **状态：接口边界提案，不是现有 TypeScript API 文档。** 当前任务上下文确认了各模块职责，但没有提供可据以断言的完整函数签名或数据类型。本文件中的字段和流程均为待 Lead、模块 Agent 与项目负责人确认的契约方向；不得据此在 Wave 0 实施运行时代码。

## 通用约定

- **权威状态只有一个写入者。** 共享游戏状态由已批准的游戏系统管理；UI 和 AI 等消费者不直接写入。任何新状态字段、持久化格式或动作类型均须经接口评审。
- **意图与执行分离。** 消费者可以请求或展示，拥有规则的系统验证、裁决和执行；失败、拒绝、超时和过期请求必须有明确、可测试的结果。
- **接口记录必填：** 生产者、消费者、输入/输出及版本、错误/降级行为、状态写入者、是否存档、兼容策略和对应测试负责人。
- **未知不得补猜。** 未定义字段、错误语义、兼容承诺或持久化要求一律标为 TBD，先达成书面约定再开发。
- 跨模块变更先更新本契约提案并获 Lead 批准；具体实现和接线由 Lead 统一集成。

## IF-NAV-01：导航与楼层切换

| 项目 | 契约提案 |
|---|---|
| 生产者/权威方 | NAV 模块；楼层切换的场景接线由 Lead 管理。 |
| 消费者 | 游戏场景、交互层和只读显示层（具体调用方待核对当前代码）。 |
| 输入 | 一次导航/快捷通路意图及必要的当前世界上下文。实际字段、楼层标识和交互身份均 **TBD**。 |
| 输出 | 成功/拒绝结果及权威落点、访问/状态变化摘要；精确结构 **TBD**。 |
| 关键不变量 | 报价和实际扣费必须来自同一权威计算或经明确等价证明；报价、扣费、跳跃层数与落点一致。E/F 交互不得重复提交。失败不得留下半完成状态。 |
| 写入/持久化 | 楼层位置、访问记录和存档字段的权威写入者、事务边界及兼容策略，须对照当前存档实现确认；不得由 UI 或内容模块自行写入。 |
| 错误/降级 | 无效路线、门禁拒绝、重复或过期交互的返回语义及恢复行为 **TBD**；应有专项测试。 |
| 测试责任 | NAV 负责模块级导航测试；QA 负责真实键盘流程、边界回归和端到端验收。 |
| 当前依赖 | `GameScene.ts` 为集成表面；在确认场景所有者和报价/扣费规则前，不对该共享文件并行开发。 |

## IF-VIS-01：UI 展示与玩家操作

| 项目 | 契约提案 |
|---|---|
| 生产者/权威方 | 游戏系统产生状态；各规则模块产生经授权的可展示结果。具体现有 ViewModel/API **TBD**。 |
| 消费者 | VIS 组件和视觉测试。 |
| 输入/输出 | UI 接收只读状态/展示数据；用户操作作为意图分发给权威系统。组件签名、事件路由及可访问性结构 **TBD**。 |
| 关键不变量 | UI 不自行计算交易结算、物品价值、导航费用或 NPC 决策，不直接改变共享状态；不得以展示数据替代规则校验。 |
| 错误/降级 | 缺少资源、无效/过期操作应有可理解反馈；既有错误行为需实测后记录，不能在本草案中假定。 |
| 写入/持久化 | 展示层不拥有权威存档状态。设置、焦点或 UI 暂态是否存档须逐项确认。 |
| 测试责任 | VIS 负责组件视觉/交互测试；QA 验证关键分辨率、键盘操作、遮挡及实际游戏画面。 |
| 当前依赖 | `GameScene.ts`、`uiKit.ts` 在共享文件冲突计划批准前不由 VIS 改动；先审查 PR #4 中尚未进入基线的候选内容。 |

## IF-NPC-01：NPC 建议、规则裁决与执行

| 项目 | 契约提案 |
|---|---|
| 生产者 | AI-NPC 运行时生成**动作建议**；Spark 或其他模型不是游戏状态的权威来源。 |
| 消费者/裁决方 | `rulesExecutor` 校验建议；所属游戏系统执行通过的动作。确切函数/Schema/动作类型须从当前基线核对。 |
| 输入 | 经过许可的 NPC 人格、记忆和可见事件上下文；可见边界与跨存档隔离规则须以代码和设计约束确认。 |
| 输出 | 可验证的建议、明确拒绝或安全回退；模型输出不得被视为已执行事实。 |
| 关键不变量 | AI 不直接修改 `GameState`，不凭空创造物品、金币或剧情事实，不跳过交易、战斗、生存等规则。任何新增动作类型须单独批准及专项测试。 |
| 错误/降级 | Spark 不可用、超时、非法输出、会话关闭后迟到响应必须可控；安全回退路径应可用 mock 复现。 |
| 写入/持久化 | 记忆与存档字段的隔离、生命周期、版本兼容及异步写入责任 **TBD**；不得提交密钥、权重、缓存或私密日志。 |
| 测试责任 | AI-NPC 为 `NpcAutonomy` 等模块提供隔离单测和离线/超时/非法输出 mock；QA 做跨模块回归。 |

|---|---|
| 生产者 | GAMEPLAY 设计独立、可验证的内容数据和资源/事件描述。 |
| 消费者 | 尚未确定。当前审计发现没有已确认的任务运行时接口。 |
| 输入/输出 | 采用何种 Schema、稳定 ID、前置条件、奖励/资源引用、随机性和版本号均 **TBD**；GAME-001A 先提议，不连接主流程。 |

## IF-QA-01：测试与集成证据

- 模块 Agent 对其功能和改动范围内的测试负责，QA 独立检查复现性、回归和用户路径；QA 不代替规则所有者决定产品行为。
- 每个交付需记录 typecheck、单测、build、相关 E2E、完整 E2E 是否执行、真实操作证据、失败项及原因。未执行不得写成通过。
- CI 的 E2E 门禁当前被审计摘要描述为非阻断；修改门禁、删测或弱化断言不是本接口的默认权力，须 Lead 明确批准。
- 测试计数、CI 产物或失败归因存在矛盾时，以可复现的具体命令/运行和原始报告为证；当前矛盾先登记，不推断哪个数字为准。

## 批准与变更控制

本文件确认前，所有接口均是讨论基线而非可编码规范。每次接口变更必须标记变更原因、影响方、迁移/兼容策略、测试和批准人，并在集成日志记录对应 PR 与 SHA。共享状态、存档格式、核心玩法规则、新 NPC 动作权限或 CI 门禁均属于高影响变更，须单独审查；Wave 0 不批准这些变更。
