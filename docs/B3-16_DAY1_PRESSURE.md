# B3-16 · 第一天压力前移（产品经理评审 P0）

**里程碑 M1 · B3 收尾 · 2026-10-29**

## 问题（来自 PM 评审 + 试玩数据）

[M1_PLAYTEST.md](M1_PLAYTEST.md) 实测：开局饥渴 79.8，衰减 2–3 点/游戏小时，**第一天 14 个醒着的小时才掉 42 点**——新玩家第一天看不到生存槽变化，水的管理决策（设计核心）实际发生在第二天（睡醒渴 23）。同时满包规则不可解释：可合并的堆静默放行、新堆拒绝，UI 零说明，试玩原话「玩家被拒三次才知道规则」。

## 改动（两项，合计约两小时）

### 1. 起始值 80 → 65（`config/game-balance.json`）

不动衰减率（动它会狠狠砸穿 7 天预算不变量，见 `survivalBalance.test.ts`），只降起点：

| | 改前 | 改后 |
|---|---|---|
| 20:00 到家（不喝水） | 渴 38 | **渴 23** |
| 第二天醒（不喝水） | 渴 23 | **渴 8** |
| 第一天槽位可视跌幅 | 42% | 57% |

效果：忽视水的玩家第一天就进危险区、第二天醒在 8 点——「水是硬的」这个教训从第二天提前到第一天晚上，且仍然可救（起始 3 瓶净水 = 90 点余量；备水先行策略变成真实的第一天决策而不是第二天的补救）。7 天薄利闭合不变量保持绿色（`survivalBalance.test.ts` 21 条全过）。

### 2. 满包规则写进 UI（`src/scenes/GameScene.ts` 三处）

- 容器·全拒：`背包已满：新物品放不下，能叠进已有堆的才能进包`
- 容器·部分合并：`叠放进的已入包；新物品放不下（背包已满），剩余留在容器`
- 地面拾取：`背包已满：新物品放不下，能叠进的堆才能拾取`
- 常驻警告追加：`；能叠进已有堆的物品仍可拾取`（保留 e2e 钉住的子串 `否则搜刮会留在原处`）

规则真实性已在 `LootSystem.ts` 代码层证实：`addItem` 的 `overflow>0` 整堆原子拒绝，可合并堆（overflow 0）静默放行——文案与代码一致，不是营销话术。

## 顺带修的测试债

`survivalSystem.test.ts` 两处：① 「按配置速率衰减」硬编码 `80 - loss`，改为读 `GAME_CONFIG.player.*Start`（这正是项目 config 哲学警告的数字漂移，数值一调就假红）；② 帧/跳转等价断言用四舍五入相等，起始值一改总量恰落 .5 边界被浮点尘决定红绿，改为 0.5 容差。
