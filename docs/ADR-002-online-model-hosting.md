# ADR-002：线上创空间使用托管云模型的例外裁决

- **日期**：2026-11-25
- **状态**：已接受（覆盖 ADR-001 中「云 API 依旧禁止」一句的适用范围）
- **决策人**：项目负责人
- **触发**：A7 交付审查提出「线上运行方式与治理文档冲突」

## 1. 冲突事实

| 位置 | 原文 | 线上实际 |
|---|---|---|
| `docs/02_TECH_SPEC.md` §1 | 「不使用服务器、实时后端、数据库、外部 AI/模型 API」 | 有服务器（`server/npc-proxy.mjs`），有外部模型 API |
| `docs/02_TECH_SPEC.md` §1 边界 | 「唯一例外是 DGX Spark 局域网推理……**云 API 依旧禁止**」 | 创空间跑在魔搭，上游是 `https://api-inference.modelscope.cn/v1`，线上实例实配模型 `Qwen/Qwen3.8-Flash-Next`（由 `NPC_MODEL_ID` 固定，见部署运行日志） |
| `docs/plans/2026-11-11-ai-npc-spark-integration-rfc.md` §21 | 「无云 API、无账号系统、无付费服务、无联机依赖」 | 有云 API、有账号（魔搭）、有免费额度上限 |

结论：**冲突是真实的，不是文档表述问题。** 不能靠改措辞糊过去。

## 2. 为什么线上必须用托管模型

这不是偏好，是物理约束：

1. **DGX Spark 是局域网设备**。评委从公网访问创空间时，浏览器无法解析到我们实验室的 Spark。RFC 里的 Ollama 直连只在「开发者本机 + 同一局域网」成立。
2. **Spark 通道需要隧道**。`spark-tunnel.sh` 存在，但把实验室内网端口暴露到公网意味着任何人可以打进来，密钥与数据都不可控。不为了演示做这件事。
3. **创空间本身要求 HTTP 服务**。魔搭容器里必须有一个监听端口的进程，纯静态站也要它。`server/npc-proxy.mjs` 因此存在，这是平台形态决定的，不是我们额外引入后端架构。

## 3. 裁决

**分三种运行模式，各自标注来源，互不冒充。** 这条同时是演示视频与 Judge Mode 的硬要求（路线 R3 原文：「必须明确区分 ModelScope 云端模型、Spark 本地推理与规则降级，不允许把三种运行模式拼接成一次虚假的完整运行」）。

| 模式 | 何时生效 | 模型 | 决策来源标记 | 玩家可见 |
|---|---|---|---|---|
| `proxy` | 线上创空间（默认） | 魔搭 API-Inference 托管模型 | `decisionSource='model'` | 是，标注「云端」 |
| `ollama` | 开发者本机 + Spark 局域网 | 自建 DGX Spark | `decisionSource='model'` | 是，标注「本地」 |
| 规则降级 | 上游不可达 / 未配 Key / 超预算 / 熔断 | 无 | `decisionSource='offline-fallback'` | 是，标注「降级」 |

`02_TECH_SPEC.md` §1 相应修订：把「云 API 依旧禁止」改为「生产环境使用平台托管的模型服务；自建推理仅限本地研发，不作为线上依赖」。

## 4. 这条裁决换来了什么，代价是什么

**换来的：**
- 评委打开链接就能看到真实模型在跑，不需要我们做任何环境准备。
- `decisionSource` 三态让「哪一次是模型决定的」可审计，不是口头声称。

**代价（必须写进交付文档，不许藏）：**
- 线上不是「无外部依赖」的。上游挂了游戏仍可玩（降级到规则脑），但那一刻不是 AI 在决策。
- 有每日预算上限（`NPC_DAILY_BUDGET=1800`）与单会话限流（12 次/分钟）。评委密集试用时会看到 429——这是设计行为，不是 bug，需要在提交说明里讲清楚。

## 5. 不受本裁决影响的部分

- **ADR-001 对 DGX Spark 的授权继续有效**。Spark 仍是研发侧的推理中心，`alinModelLoop.spark.test.ts` 这类真实推理测试继续跑在它上面。
- **「无数据库」这条没有被推翻**。存档仍走 LocalStorage，创空间容器内无持久化数据库；`server/` 只有进程内限流计数器，重启即清零。
- **「推理不可达时游戏必须完全可玩」这条是硬约束**，比任何模式标注都优先。降级路径必须有测试守着（`competitionRuntime` 的 fallback 端口三处死代码就是这个约束的抓手，已修）。

## 6. 遗留

- `docs/SPARK_DEPLOY.md`（A7 产出）描述的是本地研发部署，需要在开头加一句「线上不使用此路径」，避免读者误以为线上跑的是 Spark。
- 提交材料里「技术栈」一栏必须同时写清两条：线上托管模型、本地自建推理。只写一条都是失真。
