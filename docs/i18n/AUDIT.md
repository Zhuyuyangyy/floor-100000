**结构性问题**（比排名更值得记录）：

1. **`GameScene.ts` 是万能字符串桶**：306 条里 HUD、选项、面板、战斗、商店、提示六种职责混在一个 8000+ 行的场景文件里，抽取时必须按职责先分层，否则 key 命名必然打架。
2. **插值风格三种并存**：`${n}` 数字插值、`${item.displayName}` 跨表引用、`${container.label}` 运行时标签拼接。第三种意味着**容器标签必须先入典，楼层文案才能入典**——有依赖顺序。
3. **显示名散落多处**：物品名在 `items.ts`，怪物名在 `monsters.ts`（注释里已手写英文名！），NPC 名在 `npcs.ts`，角色名在 `metaProgress.ts`——同一个「阿林」四个来源。入典时要以数据源为属主，显示处只引用 key。
4. **分隔符焊死在文案里**：如 NightSystem 的 `' · 夜里好像有人来过……'`，前缀 ` · ` 是拼接逻辑不是文案。字典值已剥离子符（见 `zh-CN.ts` 的 `night.*`），接线时需把拼接还原。

## 5. 占位符与插值现状

- 234 条字符串含 `${...}`。字典骨架统一规范为 **`{name}` 占位符**（如 `{n}`、`{name}`、`{gold}`），
  替换实现留给接线工单；`index.ts` 只放 `t(key, params?)` 签名。
- 语序风险样本：`你击中{name}，造成 {n} 点伤害` → 英文必须允许 `{name}`/`{n}` 自由换位，
  禁用字符串拼接式翻译（`'You hit ' + name + ' for ' + n`）。
- 复数风险样本：`带回 {n} 瓶净水`（n=1 时「1 瓶」自然，英文需 `bottle/bottles`）。
  **骨架不处理复数**，接线时如需复数再引入 ICU MessageFormat；测试只钉占位符数量一致。

## 6. 字典骨架覆盖说明

`src/data/i18n/` 交付（本工单，零接线）：

- `zh-CN.ts`：语义化 key（`<域>.<对象>[.<属性>]`），值 = 现有中文原文（剥离开头拼接分隔符）。
- `en-US.ts`：同 key 英文翻译，Steam 商店页级质量，术语遵 `GLOSSARY.md`。
- `index.ts`：仅字典类型（`I18nKey`/`I18nParams`/`I18nDictionary`）与 `t(key)` 函数签名，无接入逻辑。
- `src/tests/i18n.test.ts`：key 对齐、占位符数量一致、英文显示宽度 ≤ 中文 3 倍。

覆盖策略：**全部标签类全量收录 + 叙事类抽样收录**（抽样证明长文模式可走同一条管道）。

| 覆盖层 | 状态 |
|---|---|
| 物品名（24）、容器标签（21 类代表形）、怪物名（15）、NPC 名/职衔（7+7）、角色名（5） | 全量 |
| 楼层类型（5）、区段名（6）、威胁等级（6）、配方（13）、遗物（5）、模式（3）、产业（3） | 全量 |
| 前 6 层楼层名+描述（12） | 全量（7–55 层约 270 条**未收**，机械可批量） |
| HUD/菜单/面板/按钮/提示/战斗/商店/终局选项 | 全量 |
| 任务标题、NPC 台词、独白、纸条、墙饰描述 | 各抽样 2–4 条（证明模式） |
| 遭遇氛围文、日记条目全文、保存校验、LLM prompt | **未收**（C/D 难度，见 §7） |

容器标签的三变体（如 `柜子/储物柜/铁皮柜`）只收每类代表形（21/63），
其余 42 条变体与楼层 7–55 的文案同属「机械可批量」，留给接线工单用脚本补，不入骨架。

## 7. 接入建议（分阶段，每阶段可独立验证）

1. **阶段 0（本工单）**：字典骨架 + 术语表 + 对齐测试。零运行时行为变化，合入零冲突。
2. **阶段 1**：接入 `t()` 实现（占位符替换 + locale 状态源），先只接**纯标签类**（A 难度，~600 条中的 UI 部分）。
   验证：UI 截图逐屏比对 + `i18n.test.ts` 持续全绿。
3. **阶段 2**：接数据表（物品/怪物/NPC/配方/楼层模板），把 `displayName` 改为 t(key) 查表。
   注意依赖顺序：**容器标签 → 楼层文案**（`${container.label}` 拼接依赖前者入典）。
   验证：既有 1811 项测试全绿（数据形状不变，只换取值方式）。
4. **阶段 3**：接长叙事（任务/结局/独白/遭遇）。每章需母语审校，建议按剧情段落分批。
5. **阶段 4**： locale 切换入口（设置项/启动参数）、英文窄屏排版回归（英文普遍长 1.5–2.5 倍，
   HUD 与选项按钮是高风险区，`GameScene` 的 fixed-width 文本对象需逐屏验证）。

## 8. 未处理干净的地方 / 风险

1. **容器标签变体 42 条、楼层 7–55 文案 ~270 条未入典**——机械可批量，故意留给接线工单（脚本生成），
   避免骨架体积失控。
2. **测试文件 1281 行中文未清点**——断言文案随实现走，接入后测试断言本身也要双语化，
   工作量大，建议接线阶段用「测试断言查字典」的方式消化，不单独立项。
3. **`SaveSystem`/`config` 校验错误未入典**——含 `${key}` 字段路径拼接，译文价值低，
   且错误文本改动可能影响既有测试断言（如 `save.test.ts` 钉了中文错误串），需连带更新测试。
4. **复数与性别**——`{n} 瓶`、`{n} 个` 在英文需单复数；本骨架不处理，接线时若引入 ICU
   MessageFormat，`i18n.test.ts` 的占位符断言需同步升级为「解析后的 AST 一致」。
5. **英文膨胀的排版风险未实测**——宽度测试只保 3 倍上限，不保可用；窄屏 HUD（如底部六槽导航）
   需接线后真机截图回归。
6. **`ai/prompt.ts` 的 LLM 提示词保持中文**——NPC 行为由本地模型驱动，提示词语言与模型能力绑定，
   贸然英译可能改变行为分布；建议英文版先用「中文 prompt + 英文 UI」跑稳定性再决定。
