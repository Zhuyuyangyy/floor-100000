# B3-UI-07：首五层手机竖屏可玩性

## 做了什么

手机竖屏不再把 16:9 游戏画面缩成一条难以操作的窄图，而是使用 Phaser 的 ENVELOP 显示模式，并把游戏相机裁到屏幕实际可见的中央窄视口。设计画布仍为 1280×720；360×800 竖屏的可见设计宽度为 324，320×800 为 288。横屏仍使用原来的 FIT，网页容器继续居中画布并禁止滚动和浏览器默认触摸手势。

标题、操作说明和角色选择在竖屏下收成窄幅布局；游戏 HUD 压缩为两列状态条和独立的主线/每日目标、环境信息；背包面板采用适合手机的单栏布局。320px 宽度的第二列状态数值和底部按钮都按可见宽度计算，不会跑出相机裁切区域。

底部新增简洁矢量触控按钮：按住左右箭头移动，点 E 交互，点 I 开关背包，点 C 开关制作。移动仍走既有方向输入、速度、加速度和体力系数流程；E/I/C 调用原有动作处理。面板打开时移动仍被阻止，工具按钮保留以便关闭面板。正常松手、画布外松手、浏览器 `pointercancel`、窗口失焦和切到后台都会清除触控方向。

本轮没有生成新美术，也没有改动移动数值、战斗/伤害、物品、分数、存档或楼梯规则。桌面键盘操作和浏览器 Phaser 架构保持原样。

## 验证结果

- `npm run typecheck`：通过。
- `npm run test`：58 个测试文件、762 项通过。
- `npm run build`：通过。构建仍报告约 1.61 MB 的压缩前 JavaScript 主包超过 500 KB 建议阈值；这是性能/拆包提示，不影响构建成功。
- `npx playwright test e2e/portraitTouch.spec.ts --workers=1`：4/4 通过。覆盖 360×800 新局、触控走到真实首层柜子并交互、背包开关、松手/取消后停步、320×800 HUD 与按钮边界、桌面键盘移动，以及改变方向后重新载入时正确采用横屏布局。
- `npx playwright test e2e/hudLayout.spec.ts e2e/menuMouse.spec.ts e2e/panelMouse.spec.ts e2e/smoke.spec.ts --workers=1`：13/13 通过，覆盖桌面 HUD 多视口、地图返回、标题菜单、角色选择、背包、制作和启动流程。
- `npx playwright test e2e/survivalJourney.spec.ts --workers=1`：1/1 通过。测试真实走过第 1 至第 5 层、返回宿舍并睡觉，没有传送或注入游戏状态。

浏览器测试使用 Playwright 独立上下文，不复用用户个人浏览器配置或存档。

## 取舍与未覆盖项

布局和 Phaser 缩放模式在页面启动时按当时方向确定；运行中直接旋转或改变视口方向暂不动态重排场景。改变方向后请重新载入页面，再开始或继续游戏。自动化已覆盖“启动时竖屏”和“转向后重新载入以启用横屏”的路径，但不覆盖进行中旋转。

手机按钮没有增加 M 地图入口。地图总览还没有竖屏适配，因此从触控入口打开会造成横向裁切；手机用户暂时仍需实体键盘的 M 键。首层真实触控流程已测，首五层完整旅程则用原有键盘流程验证；完整五层触控操作尚未作为单独 E2E 路径验证。
